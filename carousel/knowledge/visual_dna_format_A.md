# Visual DNA — Формат A (бренд личности)

**Когда использовать:** темы про путь новичка, мифы, механику профессии, инсайты, экспертность — когда нужно лицо бренда.

## Палитра

- Фон: `#EFEAE0` (cream-beige), без клетки
- Акцент: красный `#E63A1F`
- Текст: чёрный `#1A1A1A`, белый `#FFFFFF`

## Типографика

- Основной шрифт: **Inter**
- Заголовки: weight `900`
- Текст: weight `700-800`
- Системные macOS + Google Fonts (Playwright resolve)

## Структура

🔴 **Жёсткий лимит — 10 слайдов** (9 контентных + 1 финальный, см. SKILL.md правила 1 и 4). Старые «11-12 / 16 / 20» — устарели.
- Слайд **1** = фото лица бренда + интрига (обложка); если `materials/фото_автора/` пуста — типографская обложка
- Слайды **2-9** = контент (типографика + визуальные слоты по таблице)
- Слайд **10** = финальный слайд «Подпишись, чтобы не потерять» (`{"layout":"cta"}`, ник по центру крупно)

## Визуальные слоты (фото + видео) — детерминированная таблица

Формат A фото-центричный, визуальный слот = **фото ИЛИ видео-фон** (из `materials/video_bg/`). Размещение детерминированное, не «на глаз».

**Принципы:**
1. Слайд **1 (обложка) = ВСЕГДА фото** — сильный статичный хук, читается лучше движения.
2. Визуальный слот примерно **каждые 2-3 слайда**.
3. 🔴 **Ровно 1 видео-слот на карусель** (средний контентный слот). Не 2-3 — лимит 10 слайдов = всегда одно видео. Остальные визуальные слоты = фото.
4. Слайд **10 = финальный слайд** «Подпишись, чтобы не потерять» (правило 4) — отдельно, в таблице слотов ниже не считается.
5. 🟡 **Медиа-папки — заглушки.** Пока `materials/фото_автора/` и `materials/video_bg/` пусты, фото-слоты верстаются типографикой, видео-слот — статикой (движок предупреждает). Таблица ниже включается полностью, когда медиа появятся.

| Всего слайдов | Контентные | Визуальные слоты (среди 1-9) | Фото | Видео | Слайд 10 |
|---|---|---|---|---|---|
| 8  | 7 | 1, 3, 5     | 1, 3    | **5** | финал «Подпишись» |
| 9  | 8 | 1, 3, 6     | 1, 3    | **6** | финал «Подпишись» |
| 10 (стандарт) | 9 | 1, 3, 6, 9 | 1, 3, 9 | **6** | финал «Подпишись» |

> Итого на стандартной карусели (10 слайдов): **3 фото лица бренда + 1 видео-фон** среди контента + финальный слайд 10. Это «красивая» плотность для бренд-личности — не перегружено и не пусто.

Подбор клипа и техника наложения текста на видео — `workflows/video_backgrounds.md`.

## 🎲 Подбор фото — РАНДОМ из индекса (чтобы карусели не повторялись)

Фото лежат в **`materials/фото_автора/`** (🟡 сейчас заглушка — см. `README.md` в папке). Описание — необязательный `photos_index.json` там же; без него движок берёт все JPG/PNG папки. Каруселей много → подбор **случайный**, не «лучший». Так ничего не повторяется само собой.

🔴 **Правило выбора:**
1. **Обложка (слайд 1)** = **случайное фото среди вертикальных** (`format: vertical`). Горизонталку на обложку нельзя (ломается в 4:5).
2. **Контентные фото-слоты** = случайные фото из индекса. Без повторов внутри одной карусели (один кадр = один раз).
3. **Реальный рандом — через shell, не «на глаз»** (LLM плохо рандомит). Пример:
   ```bash
   python3 - <<'PY'
   import json, random
   d = json.load(open("materials/фото_автора/photos_index.json", encoding="utf-8"))
   ph = [p["filename"] for p in d["photos"]]
   vert = [p["filename"] for p in d["photos"] if p.get("format") == "vertical"]
   cover = random.choice(vert)
   rest = random.sample([f for f in ph if f != cover], 3)   # фото-слоты по таблице (03, 09 …)
   print("COVER:", cover); print("PHOTOS:", rest)
   PY
   ```
   Проще всего — `"photo":"auto"` в `slides.json`: движок сам выберет рандомом с памятью между каруселями.
4. Видео-слот (1 на карусель) — случайный клип из `materials/video_bg/video_bg_index.json`.
5. НЕ открывай JPG/PNG через `Read` и не переописывай фото. Нужен визуальный контроль кадра — сначала `sips -Z 700` в черновики.
6. **Индекс фото обновлять НЕ перед каждым рендером** — только если добавил/удалил фото (см. `workflows/render_format_A.md` → Шаг 1).

## 🔴 Полноэкранный визуал (edge-to-edge) — обязательно

Любой визуал на слайде (фото, Higgsfield-объект, видео) **заполняет весь кадр 1080×1350**. Текст всегда ПОВЕРХ — внизу на градиенте или на чистой зоне визуала. **НИКОГДА не ставить картинку маленькой плашкой/тайлом в углу** — это выглядит дёшево («воткнул сбоку»).

Две рабочие раскладки контентного слайда с визуалом:

1. **Full-bleed + текст снизу**: визуал на весь кадр, внизу градиент + заголовок/список. Для Higgsfield-объектов — генерировать в композиции «объект вверху, низ пустой под текст» (см. `prompts/higgsfield_3d_object.md`).
2. **Фото-плашка на всю ширину сверху + кремовая панель снизу**: фото-полоса 1080×~580 edge-to-edge, под ней кремовая панель с заголовком + списком. Тоже edge-to-edge, не тайл.

Выбор: если на слайде есть список из 4-5 пунктов — обе раскладки ок; если короткий хук/тезис — раскладка 1 (full-bleed) смотрится премиальнее.

**Запрещено:** объект/фото в маленьком прямоугольнике в углу ради «свободного места под текст». Если текст не помещается поверх — уменьшай объём текста или дроби на 2 слайда, но визуал оставляй полноэкранным. (SKILL.md правило 25.)
