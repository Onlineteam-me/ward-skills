# Финальная сдача карусели — структура папки

> Пользователь должен сразу видеть утверждённую карусель, не копаясь в служебных файлах.

---

## Правило

В `готовые/<название карусели>/` остаются **только финальные файлы**. Всё остальное → подпапка `черновики/`.

## Что лежит В КОРНЕ (финал)

```
готовые/<название>/
├── 01_<slug>.png       ← cover
├── 02_<slug>.mp4       ← видео-слайд = ТОЛЬКО mp4 (см. правило ниже)
├── 03_<slug>.png
├── ...
├── NN_<slug>.png       ← последний (обычно CTA)
└── подпись_под_пост.md  ← готовый текст подписи
```

### 🔴 Видео-слайд = ТОЛЬКО .mp4 в корне (один файл на позицию)

Если слайд видео — в корне лежит **ровно один файл `.mp4`** под номером позиции (`02_спрос.mp4`), и **БОЛЬШЕ ничего на этой позиции**:
- **НЕ класть** PNG-постер/скриншот видео рядом в корне (`02_*.png`). Пользователь сдаёт готовое в IG как есть и не будет публиковать скриншот видео отдельным слайдом — это мусор в выдаче.
- Постер/контрольный кадр (`check_NN.png`), прозрачный оверлей (`NN_overlay.png`), сырое видео — всё в `черновики/`.
- Имя без суффикса `_VIDEO`: `02_спрос.mp4`, не `02_спрос_VIDEO.mp4`. Цель — чтобы папка по сортировке читалась как ровная лента «01 → NN», один файл = один слайд.

Принцип сдачи как сотрудника: в корне лежит **ровно то, что пользователь зальёт**, без дублей и служебных версий.

## Что лежит В `черновики/`

```
готовые/<название>/черновики/
├── *_raw.png                ← Higgsfield исходники без overlay
├── *_A.png, *_B.png, ...    ← отвергнутые cover-варианты
├── 02_video_raw.mp4         ← оригинальное видео без overlay
├── generate_*.py            ← устаревшие Python-скрипты (до перехода на render.py)
├── build_*.py
├── slides.json              ← контент-файл для scripts/render.py
├── html/                    ← все HTML-исходники для Playwright
├── stas_preview/            ← превью фото для выбора
├── _cover_work/             ← временные ресайз-копии для Higgsfield
└── *_test_*.png, *_temp_*   ← любые временные файлы
```

## Когда чистить

**В конце сдачи карусели** — после того как пользователь утвердил финал. До этого момента всё может лежать вперемешку (это нормально, идёт работа).

Алгоритм сдачи:
1. Перерендерить финальные слайды (после всех правок)
2. Создать `черновики/` подпапку
3. Переместить туда всё кроме `01_*.png … NN_*.png` и `подпись_под_пост.md`
4. Показать пользователю чистую сетку 12 файлов

## Команды (для bash)

```bash
cd "готовые/<название>"
mkdir -p черновики
# переместить всё кроме финала и подписи
mv *_raw.png *_A.png *_B.png *_C.png *_D.png \
   generate_*.py build_*.py slides.json \
   html stas_preview _cover_work \
   черновики/ 2>/dev/null
```

(Обязательно `2>/dev/null` — некоторые из перечисленных файлов могут не существовать в этом проекте, и без подавления mv падает.)

## Если пользователь захочет пересобрать слайд

Все исходники лежат в `черновики/` — Python-скрипты, JSON, HTML. Можно зайти, починить, перерендерить, заменить файл в корне. История не теряется.

## 🔴 Порядок карусели на iPhone (обязательный шаг сдачи)

**Проблема:** iOS Фото и пикер Instagram сортируют **по дате съёмки (EXIF DateTimeOriginal), а НЕ по имени файла**. При переброске пачкой (Telegram/AirDrop) даты одинаковые → порядок в телефоне случайный, хотя файлы названы `01…13`.

**Фикс — прописать возрастающую дату в каждый слайд** (01 раньше всех → NN позже всех), шаг 1 минута:
- Картинки: сохранять как **JPEG** с EXIF `DateTime (0x0132)` + `DateTimeOriginal (0x9003)` + `DateTimeDigitized (0x9004)`. (PNG iOS по дате читает ненадёжно → для сдачи перегонять в JPEG quality 95, subsampling 0.)
- Видео-слайды: `ffmpeg -i in.mp4 -c copy -metadata creation_time=<ISO> out.mp4`.
- Дополнительно `touch -t` (файловая дата) — как страховка.

Инструмент: `render.py` сам проставляет EXIF-даты через `exiftool` (`brew install exiftool`). Если его нет — использовать **Pillow** (ставится в тот же venv, что и playwright): короткий скрипт пишет `DateTimeOriginal` по возрастанию.

**Почему это надёжно срабатывает:** монотонные даты собирают все слайды в один смежный блок в ленте (не разбросаны среди других фото), а на каждом слайде виден счётчик `NN/TT` — пользователь тапает по порядку. Направление сортировки (asc/desc) у разных версий IG разное — счётчик на слайде снимает неоднозначность.

**Совет пользователю при сдаче:** перекидывать через Telegram **«Отправить как файл»** (не «как фото» — там пережатие и EXIF слетает). Тогда дата сохраняется и порядок держится.
