# Архитектура конвейера: новость → контент → публикация

5 таблиц в одной базе Teable `{{TEABLE_BASE_ID}}` (адрес API — `{{TEABLE_API_URL}}`). ID всех таблиц и вью — в `config/settings.yml`, там же заглушки `{{...}}`, которые надо заменить.

```
⓪  ИСТОЧНИКИ ({{TEABLE_TABLE_SOURCES}})              ← реестр фидов, читает fetch_sources.py
         │
①  ОТОБРАННЫЕ НОВОСТИ ({{TEABLE_TABLE_SELECTED}})    ← поверхность редактора
    parsing-ward пишет → Статус «Новое» (оценка ≥7)
    Редактор: Статус «Утверждено» + правит «Рекомендация» (нужные форматы)
    Отклонённое → teable.py sweep → ОТСЕЯНО ({{TEABLE_TABLE_REJECTED}})
         │ make_unit переносит строку
         ▼
②  ЕДИНИЦЫ КОНТЕНТА ({{TEABLE_TABLE_CONTENT_UNITS}}) ← поверхность модели (ВСЕ форматы в 1 строке)
    беру Утверждённое → делаю карусель/тред/статью/видео
    кладу в поля Карусель/Подпись/Тред/Статья RU·EN/Сценарий видео
         │ (опц.) link «Публикации»
         ▼
③  ПУБЛИКАЦИИ ({{TEABLE_TABLE_PUBLICATIONS}})       ← /zernio-posting публикует и архивирует
```

🔴 Продакшн идёт в **«Единицы контента»** (мультиформатная), НЕ в «Публикации». «Публикации» = финальная витрина того, что вышло.
Редактор касается в основном **одной** таблицы — «Отобранные новости».

## 🔴 Что создать в Teable перед первым запуском

Имена полей — **ровно такие** (скрипты обращаются к полям по имени). Типы — Teable.

### ⓪ «Источники»
| Поле | Тип | Значения / примечание |
|---|---|---|
| Название | Однострочный текст (primary) | «Cointelegraph» |
| Тип | Одиночный выбор | `RSS` / `Сайт` / `Telegram` / `Twitter` |
| Адрес | URL или текст | адрес RSS или страницы |
| Кластер | Число | 1–5 (см. `knowledge/sources_and_fetching.md`) |
| Активен | Чекбокс | скилл читает только отмеченные |

### ① «Отобранные новости» (порядок колонок)
| # | Поле | Тип | Примечание |
|---|---|---|---|
| 1 | **Заголовок** | Однострочный текст (primary) | оригинал (часто EN/UA) |
| 2 | **Заголовок (RU)** | Однострочный текст | перевод/короткое RU-название |
| 3 | **Дата парсинга** | Дата | ставит `teable.py write` |
| 4 | **Дата новости** | Дата | дата самого материала |
| 5 | **Суть** | Длинный текст | суть + «💡 Почему важно:» (что это значит для новичка) |
| 6 | **Ссылка на источник** | URL / текст | только чистый URL |
| 7 | **Статус** | Одиночный выбор | `Новое` / `Утверждено` / `Отклонено` |
| 8 | **Рекомендация** | Множественный выбор | `Карусель` / `Тред` / `Статья` / `Видео (сам)` / `Видео (аватар)` |
| 9 | **ID** | Число | `YYYYMMDD###` (дата + счётчик за день), ставит скрипт |
| 10 | **Релевантность** | Число | 1–10 (см. `knowledge/scoring_rubric.md`) |
| 11 | Комментарий | Длинный текст | необязательно |

Вью `{{TEABLE_VIEW_SELECTED}}`: Grid, сортировка «Дата парсинга» ↓ (новое сверху).

### «Отсеяно (калибровка)»
Зеркало «Отобранных»: `Заголовок · Заголовок (RU) · Дата парсинга · Дата новости · Суть · Ссылка на источник · Рекомендация · Релевантность · ID` + **Дата отсева** (Дата). Сюда `sweep` переносит отклонённое, а `reject` пишет 2–3 низких примера за прогон — это калибровка рубрики.

### ② «Единицы контента» (выровнена под 5 форматов, зеркало новостей)
| Поле | Тип | Что лежит |
|---|---|---|
| Заголовок (RU) | Однострочный текст (primary) | короткое RU-название (= имя локальной папки) |
| Статус | Одиночный выбор | `Принято` (ставит скрипт) / `На правки` (ставит редактор) |
| Форматы | Множественный выбор | те же 5 форматов |
| Заготовка | Длинный текст | глубокий разбор источника (правило #13) |
| Ссылка на источник | URL / текст | копируется из новости |
| Подпись к карусели | Длинный текст | полный текст подписи |
| Карусель | Вложения | JPG/MP4 слайды (опционально) |
| Тред | Длинный текст | посты с маркерами `Пост N/TOTAL` |
| Статья RU / Статья EN | Длинный текст | полный текст |
| Сценарий видео (сам) | Длинный текст | полный сценарий |
| Сценарий видео (аватар) | Длинный текст | текст для озвучки + заметки по визуалу |
| Drive папка | Однострочный текст | **локальный путь** к медиа (начинается с `storage.local_root`) |
| Post Insta | Одиночный выбор | `Не опубликован` / `Опубликован` |
| Threads пост | Одиночный выбор | `Не опубликован` / `Опубликован` |
| Заголовок · Суть · Дата парсинга · Дата новости · Релевантность · ID | как в «Отобранных» | копируются из новости |
| Комментарий | Длинный текст | правки редактора, метка `inline-written` |

Вью `{{TEABLE_VIEW_CONTENT_UNITS}}`: Grid, сортировка ID ↓; `make_unit` ставит новую запись наверх.

### ③ «Публикации»
Структуру задаёт скилл `zernio-posting` (см. его документацию). parsing-ward туда не пишет.

## Хранилище исходников (только локально)
```
<storage.local_root>/{Название} {ID}/
       └─ 01_cover.jpg … 10_cta.mp4 + подпись_под_пост.md + тред.md + сценарий_видео_сам.md
```
- `storage.local_root` — заглушка `{{CONTENT_FACTORY_DIR}}` в `config/settings.yml` (абсолютный путь на компьютере клиента).
- `<ID>` — тот же, что в новости и единице контента (трассировка по одному номеру).
- В поле **«Drive папка»** «Единиц контента» пишется **локальный путь** к папке (не URL облачного диска).

## Статусы
- **Отобранные новости.Статус:** Новое / Утверждено / Отклонено (утверждённое переносится в «Единицы контента» и удаляется из inbox; «Отклонено» → sweep → Отсеяно)
- **Единицы контента.Статус:** Принято (default, ставит parsing-ward) / На правки (редактор, если просит переделать)
- **Единицы контента.Post Insta:** Не опубликован (default) / Опубликован (zernio после публикации IG карусели/Reel)
- **Единицы контента.Threads пост:** Не опубликован (default) / Опубликован (zernio после публикации Threads)

## Очередь на контент
`teable.py queue` печатает все строки `Статус=Утверждено` — это to-do для батча. После `make_unit` строка удаляется из «Отобранных» (перенос в «Единицы контента»).
