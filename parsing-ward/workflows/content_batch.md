# Workflow — батч контента (2×/неделю)

Триггер: редактор говорит «делай контент» / «возьми первые 3» / «возьми вот эту строчку».
Цель: превратить выбранные редактором утверждённые новости в единицы контента (карусели и др.).

> Команды — из папки `scripts/` скилла (`cd ~/.claude/skills/parsing-ward/scripts` или путь установки).

🔴 **Редактор выбирает, что именно взять в работу.** Модель показывает очередь (`queue`), редактор указывает конкретные строки или количество. Только выбранные строки переносятся в «Единицы контента» (и удаляются из «Отобранных»). Остальные утверждённые остаются в inbox до следующего батча.

---

## Шаг 0 — бэкап + гигиена очереди (автомат, перед началом)
```bash
python3 backup.py              # дамп 4 таблиц в storage.backups_dir/YYYY-MM-DD_HHMM/
python3 teable.py sweep        # Отклонённое (поставил редактор) → «Отсеяно» зеркально
```
Это **первые два действия каждого батча**: страховка + гигиена. Backup занимает ~30 сек, sweep моментально.

## Шаг 1 — взять очередь (движок)
```bash
python3 teable.py queue        # Статус=Утверждено (всё что в inbox)
```
Печатает: id, ID, Заголовок(RU), Рекомендация (форматы), Ссылка, Суть.
Сортировка: по `Релевантность` ↓. **Показать редактору и спросить, какие строки взять в работу.** Не брать всё подряд без его указания.

## 🚀 Ускоренный путь карусели (значения по умолчанию)

Когда строка из «Отобранных новостей» — у неё **всегда есть источник** (URL). Это значит формат **C — ньюсджекинг** (фото героя/автора + слайд-пруф источника, см. `carousel/knowledge/format_C_recipe.md`). НЕ нужно проходить долгий онбординг carousel с 4 вопросами.

**Жёсткие дефолты для каруселей из этого скилла:**

| Решение | Дефолт | Когда менять |
|---|---|---|
| **Формат** | C — ньюсджекинг | если в новости нет публичного URL (редкий кейс) |
| **Хук обложки** | Ф1 «шок-факт → что это значит для тебя» (цифра из «Сути»). Для срочной новости — Ф2 «N минут / час назад…». Если сильной цифры нет — Ф4 «Большинство думает, что…» через миф новичка. | если редактор явно сказал «возьми другой» |
| **Стиль** | стиль по умолчанию из скилла carousel (дизайн-система Ward) | стиль зашит в движке carousel |
| **Объём** | 10 слайдов: 9 контентных + 10-й CTA «Подпишись, чтобы не потерять» | жёстко (правило объёма в carousel) |
| **Апрув плана?** | На 1-й строке батча — спросить (хук+структура). На 2-й и далее — НЕ спрашивать, делать (правило «бери и делай») | если редактор сказал «реши сам» — не спрашивать вообще |

**Готовая структура 10 слайдов для формата C** (заполняй контентом из «Сути»):

| # | layout (carousel) | Что |
|---|---|---|
| 01 | `cover-photo` | фото героя/автора + хук-цифра (Ф1/Ф2) |
| 02 | `source` | скрин URL через `screenshot_url.py` + штамп «ИСТОЧНИК» (логотип/название биржи закрыть) |
| 03 | `photo-overlay` | фото + вторая цифра / контекст |
| 04 | `quote` (dark=true) | прямая цитата из источника |
| 05 | `poster` | что это значит для тебя (боль/страх новичка) |
| 06 | `poster` | механика: что произошло в стакане / почему сработали ликвидации / как устроена схема |
| 07 | `formula` | «было → стало» или «миф → правда Ward» |
| 08 | `list` | 3 пункта — как не попасть так же (стоп, плечо, проверка платформы) |
| 09 | `photo-overlay` | финал-инсайт + «Не финансовая рекомендация» |
| 10 | `cta` | «Подпишись, чтобы не потерять» (канон — `_ward/Голос бренда Ward (ToV).md`) |

> Если папка с фото героя/автора в скилле carousel пустая (заглушка) — carousel предупредит и соберёт слайды без фото (layouts `poster`/`quote`). Это не ошибка конвейера, не останавливаться.

> 🔴 **СЛАЙД-ИСТОЧНИК (02) ОБЯЗАТЕЛЕН В КАЖДОЙ КАРУСЕЛИ. НЕ ПРОПУСКАТЬ.** (правило после факапа: карусели собрали без скрина-пруфа, «потому что в юните пустое поле URL».)
> - URL берём из юнита — поле **«Ссылка на источник»**.
> - 🔴 **Если поле пустое — НЕ собирать карусель без источника.** URL всегда достаётся по **перелинку**: `Единица контента → поле «Источник» (линк) → запись в «Отобранных новостях» → «Ссылка на источник»`. Перелинк живой всегда (двусторонняя связь, см. make_unit). API: `GET /table/{Отобранные}/record/{linked_id}`.
> - Скрин: `screenshot_url.py <URL> <folder>/02_source_raw.png --validate` нужным venv-python (`carousel/config/settings.yml → env.python_with_playwright`). Путь скрина кладём в slides.json как `"screenshot"`.
> - 🔴 **Если основной источник за пейволлом / бот-блоком / SPA-ленивой загрузкой** (крупные финансовые СМИ, страницы бирж, агрегаторы ликвидаций — отдают пустой/футерный скрин) — взять чистый альтернативный пруф той же новости: **другое крипто-СМИ с этой же новостью**, **официальный документ регулятора** (страница НБУ/НКЦБФР/ESMA, текст законопроекта), **пресс-релиз киберполиции** или другой не заблокированный материал. Скрин-пруф = «я проработал источник» → подойдёт любой credible-материал.
> - 🔴 **Источник — страница конкретной биржи?** Скрин можно, но логотип и название биржи на слайде закрыть/обрезать (красная линия Ward: биржи не называем). Лучше взять пруф из СМИ.
> - Caption под скрином — назвать показанный источник (`cointelegraph.com — …`, `nssmc.gov.ua — …`), но не биржу.

Полный пример `slides.json` — `templates/slides.example.json` в скилле carousel (или загляни в любую готовую папку `<storage.local_root>/<Название> <ID>/черновики/slides.json`).

**Skipping онбординг carousel:** ты УЖЕ знаешь ответы на 4 вопроса (источник=текст, формат=C, объём=9+CTA, хук=придумай сам). Просто пиши `slides.json` и запускай `render.py` (см. Шаг 3 ниже).

## Шаг 2 — глубокое чтение источника + смысловая заготовка

Для каждой выбранной строки:
1. **Прочитать источник** — перейти по «Ссылке на источник» (WebFetch), прочитать статью/пост/тред целиком, а не только «Суть».
2. **Собрать смысловую заготовку** — структурированный разбор для всех форматов:
   - **Ключевые цифры** (точные, из источника — правило #6)
   - **Сильные цитаты** (дословно)
   - **Главный тезис** (1 предложение)
   - **Что это значит для новичка** — какой миф/страх/сегмент (`knowledge/audience_dna.md`)
   - **Контраст / сдвиг** (было → стало, старая модель → новая)
   - **Потенциальный хук** для обложки (Ф1 шок-факт → что это значит для тебя / Ф2 «N минут назад…»)
   - **Риск-оговорка** — где нужна фраза «Не финансовая рекомендация», что нельзя обещать

Заготовка = единый «банк смыслов», из которого профильные скиллы нарезают каждый свой формат. Без неё скиллы работают по «Сути» (2–3 предложения) и додумывают — с ней работают по первоисточнику.

🔴 **Заготовка записывается в поле «Заготовка» в «Единицах контента»** (longText). Это происходит при переносе строки из «Отобранных» — `make_unit` сначала читает источник, собирает заготовку и кладёт её в unit.json. Поле «Суть» (краткое из парсинга) переносится as-is и не меняется.

🔴 Если источник за пейволлом / не отдаётся — собрать по 2 фолбэк-источникам (другое СМИ + официальный первоисточник), см. правило #13. Помечать в заготовке `[источник заблокирован, собрано по <источник 1> + <источник 2>]`.

## Шаг 3 — нарезка по форматам: ОБЯЗАТЕЛЬНО вызови профильный Skill (правило #10)

Заготовку из Шага 2 передаём в каждый профильный Skill. Аудиторию/сегмент определяю по `knowledge/audience_dna.md`.

🔴 **НЕ инлайн.** Каждый формат — через профильный Skill. Это правило #10 в SKILL.md.

| Формат | ОБЯЗАТЕЛЬНО вызвать Skill | Что положить в Teable |
|---|---|---|
| **Карусель** | `Skill("carousel")` → slides.json → render.py | **Подпись к карусели** + **Карусель** (медиа) |
| **Тред** | `Skill("threads-writer")` с режимом «Переупаковка» | **Тред** |
| **Видео (сам)** | `Skill("eman-scenario")` | **Сценарий видео (сам)** |
| **Видео (аватар)** | `Skill("eman-scenario")` (вариант под аватара) | **Сценарий видео (аватар)** |
| **Статья** | инлайн допустимо (нет профильного скилла) → в «Комментарий» добавить `inline-written` | **Статья RU** / **Статья EN** |

🔴 **Призыв** (правило #11) — «Подпишись, чтобы не потерять» (канон — `_ward/Голос бренда Ward (ToV).md`). Курс, Discord, KYC, бесплатные материалы не продвигаем. Никаких дат запуска / сумм / придуманных деталей.
🔴 **Красные линии** (правило #20) — проверить каждый артефакт: нет сумм-обещаний, «заработок/доход/быстрые деньги», названий бирж, прогнозов цены; есть «Не финансовая рекомендация» там, где речь о рынке.

## Шаг 4 — локальная папка (исходники)
🔴 **Перед записью в Teable** — каждая единица получает физическую папку с исходниками локально. Облачные диски НЕ используются.

🔴 **Формат имени папки: `{Короткое RU-название} {ID}`** (RU первое, ID в конце). Примеры:
- `Ликвидации лонгов за сутки 20261027003`
- `Биржа закрыла вывод для региона 20261027002`
- `Фейковое приложение биржи 20261027001`

Короткое RU-название = 30–50 символов, понятное с одного взгляда. Не slug (не латиница, не дефисы). Можно с символами `$`, `%`, `−`, эмодзи и т.д. — macOS поддерживает.

```bash
ID=20261027003                                          # = ID новости
NAME="Ликвидации лонгов за сутки"                      # короткое RU из заголовка
ROOT="<storage.local_root из config/settings.yml>"     # абсолютный путь, заглушка {{CONTENT_FACTORY_DIR}}
DIR="${ROOT}/${NAME} ${ID}"
mkdir -p "$DIR"
# кладу всё, что произвёл: slide_01.jpg..slide_10.jpg, тред.txt, статья.md, сценарий.md, подпись.txt
# (артефакты создаются скиллами на этом же шаге — /carousel, /threads-writer, /eman-scenario)
```

🔴 **В Teable поле «Drive папка» кладём ЛОКАЛЬНЫЙ путь** (`$DIR` выше), не URL облачного диска.
Пример значения поля: `<storage.local_root>/Ликвидации лонгов за сутки 20261027003`.

Локальный корень — в `config/settings.yml → storage.local_root`. Если там осталась заглушка — `make_unit` остановится с подсказкой.

## Шаг 5 — записать в «Единицы контента» (`teable.tables.content_units` в конфиге)
🔴 **ID единицы = ID новости-источника** (наследование, прозрачная трассировка). Делается движком.

### 🔴 Жизненный цикл статусов в Единицах контента

```
Принято        ← parsing-ward ставит автоматом при создании юнита (make_unit)
   ↓
   └─→ На правки  ← редактор в UI ставит руками, если хочет переделать
          ↓
       parsing-ward видит «На правки» → переделывает по комментарию → возвращает в «Принято»

Параллельно — per-format статусы публикации:
   Post Insta     = «Не опубликован» (default) → «Опубликован» (zernio после публикации IG)
   Threads пост   = «Не опубликован» (default) → «Опубликован» (zernio после публикации Threads)
```

**Что значит каждый статус «Статус»:**
- **Принято** — материал готов к публикации (parsing-ward отдал, редактор в курсе)
- **На правки** — редактор хочет переделать (комментарий в поле «Комментарий»)

**Что значит per-format статус:**
- **Post Insta** = «Опубликован» — карусель/Reel в Instagram уже вышли (или в очереди Zernio)
- **Threads пост** = «Опубликован» — тред в Threads уже вышел (или в очереди Zernio)

При сборке `unit.json` НЕ передаю Статус и Post Insta / Threads пост — `make_unit` поставит дефолты сам:
- Статус = «Принято»
- Post Insta = «Не опубликован»
- Threads пост = «Не опубликован»

🔴 **В каждое контентное поле — ПОЛНЫЙ ТЕКСТ артефакта, НЕ отсылка.** Teable = источник правды (редактор листает таблицу и видит контент сразу), локальная папка = медиа. Запрещено «См. файл», «См. сценарий_видео_сам.md» и т.п.

| Поле в Teable | Что лежит |
|---|---|
| **Подпись к карусели** | полный текст подписи (контент + «Подпишись, чтобы не потерять» + «Не финансовая рекомендация») |
| **Тред** | 2–3 самодостаточных поста с маркерами `Пост N/TOTAL` и разделителями `———` (формат threads-writer v1.5+, см. пример ниже) |
| **Статья RU / EN** | полный текст статьи |
| **Сценарий видео (сам)** | весь сценарий: хук, блоки, ремарки, варианты длины |
| **Сценарий видео (аватар)** | полный текст для озвучки + заметки по визуалу |
| **Карусель** | attachments (JPG) — медиа |
| **Drive папка** | 🔴 **Локальный путь** к папке (`<storage.local_root>/{Название} {ID}`). Не URL облачного диска. |

Если артефакт длиннее ~50К символов — разрезать на 2 поля или сжать резюме, но НЕ заменять отсылкой.

### 🔴 Эталон формата поля «Тред» (для zernio-posting v8+)

```
Пост 1/3

<хук-строка>
<тело поста 1>

———

Пост 2/3

<хук-строка>
<тело поста 2>

———

Пост 3/3

<короткий вывод>
Подпишись, чтобы не потерять.
```

- **Маркер `Пост N/TOTAL`** — первая строка каждого поста. Regex `^Пост\s+\d+/\d+\s*$`. Zernio-posting распознает его и обрежет перед публикацией.
- **Разделитель `———`** — три em-dash отдельной строкой между постами.
- **Пачка 2-3 поста** (не 5-6): дефолтные потолки threads-writer v1.5.
- **Последний пост** — всегда вывод + призыв «Подпишись, чтобы не потерять» (канон — `_ward/Голос бренда Ward (ToV).md`).

Делается движком:
```bash
python3 teable.py make_unit ../workspace/unit.json
# unit.json (актуальная схема):
# {
#   "news_id":     "recXXX",
#   "Заготовка":   "…глубокий разбор источника после WebFetch: ≥300 симв, ≥3 цифры, ≥2 цитаты, «Было:/Стало:» — ОБЯЗАТЕЛЬНО…",
#   "Форматы":     ["Карусель","Тред"],
#   "Подпись к карусели": "…",
#   "Тред":        "…",
#   "Статья RU":   "…",
#   "Сценарий видео (сам)":     "…",
#   "Сценарий видео (аватар)":  "…",
#   "Drive папка": "<storage.local_root>/{Название} {ID}"
# }
# 🔴 БЕЗ «Концепт» / «Описание» — этих полей в схеме нет.
# 🔴 БЕЗ валидной «Заготовки» → make_unit ABORT.
```
Что делает `make_unit` автоматически:
- **Валидация**: `Заготовка` (длина, цифры, цитаты, контраст) и `Drive папка` (начинается с `storage.local_root`) — иначе ABORT (правила #13, #17 SKILL.md).
- **Дедуп**: safety-check по ID/URL/Заголовок (RU)/Заголовок — если юнит уже есть, ABORT.
- **Наследует ID** от новости (тот же `20261027003`),
- Копирует контекстные поля из новости: «Заголовок (RU)», «Заголовок», «Суть», «Ссылка на источник», «Дата парсинга», «Дата новости», «Релевантность»,
- `Post Insta` и `Threads пост` = «Не опубликован» (default перед публикацией),
- 🔴 **УДАЛЯЕТ строку из «Отобранных новостей»**. Все данные уже скопированы в юнит — строка-источник больше не нужна. «Отобранные» = чистый inbox только с необработанным.
- 🔴 **Ставит новую единицу НАВЕРХ таблицы** (правило #14) — редактор видит свежее сверху.

## Шаг 6 — (опц.) публикация
Готовое к публикации → `/zernio-posting` (Instagram/Threads) с архивацией (локально + Teable).
Пачку каруселей можно запланировать скриптом `scripts/schedule_batch.py <schedule.json>` (формат — в шапке скрипта).
Правила Zernio: 409 → не retry; scheduled_for строго в будущем; карусель ≤10 слайдов.

## 🔴 Правило обхода очереди: «строка целиком, потом следующая»
Идём **по строкам**, не по форматам. На каждую строку — все её форматы в одном заходе, пока контекст материала загружен. Карусель + тред + видео для ID 20261027001 → потом всё для 20261027002 → и т.д.

**Почему:** суть и «💡 Почему важно» прочитываются один раз → согласованные хук/цифры/тон во всех артефактах одной идеи; строка в «Единицах контента» собирается целиком; если упёрся в лимит — N идей **полностью** готовы, N+1 не тронута (чисто).

Порядок строк в очереди: по `Релевантность` ↓ (самое горячее первым). Не упираться в формат — если что-то не идёт, помечаю в `Комментарий` и двигаюсь к следующему формату той же строки.

## Масштаб
Если нужно «пачкой» 30–50 единиц контента наперёд — Большой батч режу на сессии по 3–5 строк, чтобы не упереться в контекст/лимиты.
