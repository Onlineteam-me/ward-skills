# Workflow — парсинг крипто-новостей

Цель: добыть свежее, оценить по `knowledge/scoring_rubric.md`, записать отобранное (≥7) в «Отобранные новости».
Запускается вручную (`/parsing-ward`) или scheduled-task по расписанию из `config/settings.yml → schedule`.

> Все команды ниже — из папки `scripts/` скилла: `cd ~/.claude/skills/parsing-ward/scripts` (или путь, куда установлен скилл).
> Первый запуск: `python3 teable.py check` — покажет незаполненные заглушки `{{...}}` и доступ к таблицам.

---

## Шаг 0 — бэкап таблиц (страховка, первое действие)
```bash
python3 backup.py        # дамп 4 таблиц в storage.backups_dir/YYYY-MM-DD_HHMM/
```
Покрывает Источники, Отобранные новости, Единицы контента, Отсеяно. ~30 сек. Если таблица поломается — данные восстановимы из последнего дампа.

## Шаг 1 — добыть свежак (движок)
🔴 **Сеть/песочница:** в scheduled-task Bash по умолчанию в песочнице, которая режет сеть → `fetch_sources.py` массово падает с фейковыми «DNS-ошибками» (хотя сеть на машине рабочая, ручной запуск даёт 7+ источников). Все сетевые команды (`fetch_sources.py`, `backup.py`, `teable.py`) запускать с **dangerouslyDisableSandbox=true**. Признак песочницы: DNS-ошибки на большинстве источников — перезапусти команду без песочницы.
```bash
python3 fetch_sources.py        # окно свежести из config (fetch.freshness_hours). Тест: --hours 72
```
Вернёт JSON (и сохранит в `workspace/fetch_YYYY-MM-DD.json`): группы по источникам/кластерам + блок `errors`.
Дедуп против уже записанного — встроен.

## Шаг 1.5 — 🔴 ГВАРД ДЕГРАДАЦИИ (обязательно, перед любым добором)
Деградированный прогон = `fetch_sources.py` вернул мало/ничего, потому что большинство источников упало (DNS/429/сеть) или свежих позиций < `config.scoring.min_rows`.

**Если прогон деградированный:**
- ❌ НЕ добирать архив через WebSearch, НЕ «спасать» прогон старьём.
- ❌ НЕ ставить свежие даты старому материалу (фабрикация = зомби).
- ❌ НЕ писать в таблицу вообще. Пустой прогон лучше зомби-дампа.
- ✅ Сразу перейти к Шагу 7 и уведомить: «деградированный прогон: fetch упал (X из Y источников), записано 0, не забрал: […]».

Правило свежести жёсткое: **в таблицу попадает только материал с реальной датой ≤7 дней.** Если сильный сигнал датирован неделями назад — он НЕ наш, фильтр `teable.py` его и так отсечёт; не пытаться обойти.

## Шаг 2 — добрать веб-источники (ТОЛЬКО если прогон НЕ деградированный)
JS-сайты из `fetch.js_sites` (агрегаторы ликвидаций, объявления бирж), Telegram-каналы и упавшие (429/ParseError) — через **WebSearch** с `allowed_domains`. См. `knowledge/sources_and_fetching.md`.
🔴 Только материалы **за последние 2–3 дня**. Архивные/старые (>7 дней) — не брать ни под каким предлогом.
Не обязательно каждый прогон; приоритет — кластер 1 (рыночные события) и кластер 4 (скам).

## Шаг 3 — оценить и отобрать (это делает модель, не скрипт)
Читаю каждую позицию из JSON и по `knowledge/scoring_rubric.md`:
- ставлю **Релевантность 1–10** (ось Охват × ось Конверсия под новичков Ward, см. `knowledge/audience_dna.md`);
- сразу отсекаю прогнозы цены, шилинг монет, аирдропы, «иксы» (жёсткие отсечки рубрики);
- порог записи **≥7** (`config.scoring.write_threshold`);
- перевожу заголовок (RU), пишу **Суть** = суть + «💡 Почему важно:» (что это значит для новичка, какой миф/страх, какая формула хука — Ф1 или Ф2) одним блоком;
- ставлю **Рекомендация** (форматы) по таблице угол→формат;
- **«Ссылка на источник» = только чистый URL** (без имени источника, без " — "; имя видно по домену).
Порядок: сначала кластер 1 (рыночные события), потом 2 (биржи), 3 (регулирование), 4 (скам), 5 (медиа).

## Шаг 4 — записать (движок)
Сформировать `workspace/rows.json` (массив; поля — см. `templates/selected_row.example.json`) и:
```bash
python3 teable.py write ../workspace/rows.json     # Статус=Новое, ID и Дата парсинга авто
```
Опционально 2–3 низких примера в «Отсеяно» для калибровки:
```bash
python3 teable.py reject ../workspace/rejects.json
```

## Шаг 5 — гигиена очереди
```bash
python3 teable.py sweep      # Отклонённое редактором → «Отсеяно (калибровка)»
```

## Шаг 6 — контроль качества (см. `knowledge/scoring_rubric.md` → КК)
- ≥ `config.scoring.min_rows` строк (8); ≥2 материала 9–10; кластер 1 представлен; есть скам или регулирование; без дублей.
- Если совсем пусто — не выдумывать: записать предупреждение, перечислить упавшие источники.

## Шаг 7 — уведомить
Короткое резюме: «Парсинг готов: X материалов из Y источников. Топ-3: […]. ⚠ не забрал: […].»
(В scheduled-task — через notifyOnCompletion; в интерактиве — текстом.)
