# Anti-references — банк «как делать НЕЛЬЗЯ»

Зеркало `examples/viral_refs/`, но с обратным знаком. Сюда складываем **реальные
провальные посты** (свои факапы, скрины из ленты) с разбором — чтобы скилл читал их
перед генерацией и **НЕ воспроизводил** эти паттерны.

`viral_refs/` учит, к чему тянуться. `anti_refs/` учит, чего избегать. Оба читаются
перед генерацией.

---

## Что складывать

- Свои посты, которые получились плохо (вырваны из контекста, AI-душок, мёртвый хук).
- Скрины из ленты с типовыми провалами (затёртые мотивашки, голые цифры, «это видео…»).
- Особо ценны посты с **диагнозом**: не просто «плохо», а *почему* и *какой тест провален*.

## Что НЕ складывать

- Просто слабые по теме посты без чёткого паттерна провала.
- Узконишевое, что не повторится.

---

## Формат

Один файл `anti_refs.md` с пачкой через `———`. Каждый разбор:

```markdown
### <короткий ярлык провала>
❌ <текст провального поста как есть>

🔍 Диагноз: <какой тест/правило провалено — ссылка на standalone_context.md / threads_native.md>

✅ Починка: <паттерн исправления ИЛИ «не создавать вовсе, если осколок неисправим»>
```

---

## Как скилл это использует

Перед генерацией (если папка не пуста):
1. Читает `anti_refs.md`.
2. Держит провалы как **negative examples**: сверяет черновики — нет ли того же паттерна.
3. На скоринге провал по гейту источника-сироты = veto (см. `workflows/score_and_pick.md`).

**Стартовый набор уже лежит** в `anti_refs.md`: три классических провала «осиротевшая отсылка» (примеры А/Б/В, на них построен `knowledge/standalone_context.md`) + провалы под голос и красные линии Ward. Скринов-первоисточников в пакете нет: тексты провалов приведены прямо в файле. Если папка окажется пустой — скилл не падает, просто работает без negative examples.
