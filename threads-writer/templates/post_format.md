# Шаблон формата вывода

## Правила формата

- 🔴 **Дефолт — атомарные посты (Pool), не связный тред.** Каждый пост самостоятелен, постится вперемешку через Zernio. См. `knowledge/atomic_posts.md`.
- **Длина:** микс. Из набора минимум треть — ultra-short (1–2 строки). Остальное standard (3–5). Не лонгрид.
- **Первая строка** = хук. Удар сразу. Тип хука и синтаксис первой строки — разные у соседей (матрица в `atomic_posts.md`).
- **Каждый пост самодостаточен и shuffle-safe** (см. `knowledge/cold_reader.md` + `knowledge/atomic_posts.md`).
- 🔴 **Понятен без источника:** назван конкретный субъект (нет «это видео / эту сделку / его статистика»), каждое число заякорено (нет голых «−46%», «$60 млрд»). См. `knowledge/standalone_context.md`.
- 🔴 **Никаких связок треда** в теле: «сдвиг, который», «и вот в чём», «как писал выше», «во-первых/во-вторых» через посты. Бан-лист — `atomic_posts.md`.
- **Без вводных фраз** в ТЕЛЕ поста: «Вот пост:», «Пост №1», «Итак». *(Технический маркер `Пост N/TOTAL` — это НЕ тело поста, он идёт отдельной служебной строкой над телом, см. «Структура пачки постов» ниже.)*
- Между постами — только разделитель: `———` (три em-dash). Это **технический делимитер для Zernio**, не маркер «части одной ветки».
- **Без markdown-разметки** внутри постов (нет `**жирного**`, нет `# заголовков`).
- **Без хэштегов** в постах (если пользователь не попросил).
- 🔴 **Ссылки на источники:** Ward — **внешних ссылок нет** (`config/settings.yml` → `links.external_links_allowed: false`), источник называется словами. Если ссылки разрешены: пост НАЗЫВАЕТ конкретный инструмент/статью/подкаст → URL отдельной строкой в конце (без лейбла «Источник:»); не называет → не лепить. См. `knowledge/threads_native.md` + `knowledge/post_types.md`.

## Структура одного поста

```
<первая строка — хук, останавливает скролл>
<вторая строка — конкретика / контекст / поворот>
<третья строка — вывод / поворот / вопрос>
[опц. 4–5 строки — если мысль требует]
```

## Структура пачки постов

🔴 **Формат для парсинга zernio-posting (обновлено 2026-07-09):** каждый пост открывается служебной строкой `Пост N/TOTAL`. Это **технический маркер для агента-публикатора** (zernio-posting сплитит по `———` и убирает первую строку-маркер перед публикацией — она в самом Threads-посте НЕ появится).

```
Пост 1/3

<текст поста 1 — начинается с хук-строки>

———

Пост 2/3

<текст поста 2>

———

Пост 3/3

<текст поста 3>
```

Правила:
- **Маркер `Пост N/TOTAL`** — первая строка КАЖДОГО поста, ровно этот формат (`Пост 1/3`, `Пост 2/3`, ...). Не «№1», не «Post 1», не «1 из 3». Zernio-posting распознаёт именно `^Пост \d+/\d+$`.
- **Пустая строка** между маркером и телом поста — обязательна.
- **Разделитель `———`** между постами остаётся — три em-dash отдельной строкой с пустыми строками до/после. Это физический сплиттер.
- **Тело поста НЕ содержит маркер** — он идёт «сверху над постом», агент его срежет.
- Никакой нумерации внутри самого тела поста (не «1.», не «первый пункт»).

⚠️ **Если запрошен «одиночный пост»** (не пачка) — маркер `Пост 1/1` **всё равно ставится** для единообразия. Zernio-posting может публиковать одиночный пост без сплита, но маркер помогает парсеру и читателю таблицы понять «это финальная версия одного поста, не черновик».

## Опциональные блоки (по запросу)

### 5 вариантов хука к одному посту
```
**5 вариантов хука** (выбери под настроение):

1. <вариант 1 — парадокс>
2. <вариант 2 — контра-совет>
3. <вариант 3 — провокация>
4. <вариант 4 — личная история>
5. <вариант 5 — вопрос-зеркало>
```

### Финальный CTA-пост
Последний пост — с вопросом аудитории в комментариях.
```
<основная мысль>
<вывод>
<вопрос>. Напиши в комментариях 👇
```
(Тут эмодзи допустим — один.)

### Полный разбор (если пользователь просит «покажи кухню»)
```
ЧЕРНОВИК:
<draft посты>

AI-АУДИТ:
- <тейл 1>
- <тейл 2>
- …

ФИНАЛ:
<final посты>
```
По умолчанию **не показывать**, только при явном запросе.

## Финальный sweep перед сдачей

- [ ] 🔴 **0 длинных тире** в финальном посте (поиском проверить `—` по тексту). Любое найденное заменить точкой / двоеточием / запятой / без знака — таблица в `knowledge/ai_anti_patterns.md` §12. Это правило **жёстче, чем "1-2 ок"**.
- [ ] Нет ChatGPT-вежливости («надеюсь, поможет»).
- [ ] Нет markdown-разметки внутри постов.
- [ ] Нет «как я писал выше» / отсылок к контексту.
- [ ] 🔴 **Гейт источника-сироты** (`standalone_context.md`): (1) назван конкретный субъект, нет «это/его/тот» в пустоту; (2) у каждой цифры/$/% есть хозяин; (3) панч приземляется внутри поста. Сирота → починить из источника или выкинуть.
- [ ] 🔴 **Лучше меньше, но сильных:** число постов ≤ потолка, набор не добит слабыми ради количества («drop, don't pad»).
- [ ] 🔴 Нет связок треда (бан-лист `atomic_posts.md`) — каждый пост начинает мысль с нуля.
- [ ] 🔴 Нет затёртых мотивационных зачинов: «Пока ты…» / «пока ты X, кто-то Y», «Представь, что…», «А что, если я скажу…», «Никто не говорит, но…» (см. `threads_native.md` антишаблон 6).
- [ ] 🔴 Матрица разнообразия: длина / тип хука / атрибуция / регистр различаются у соседей (≤ трети называют источник).
- [ ] 🔴 Shuffle-safety: каждый пост сработает в одиночку, в рандомной ленте.
- [ ] Нет аббревиатур без расшифровки (МСБ → малый бизнес).
- [ ] Нет рублей (только `$` / `USDT` / без валюты).
- [ ] 🔴 **Красные линии Ward:** нет сумм-обещаний, «без риска», «гарантированно», слов «доход / заработок / быстрые деньги», названий бирж/брокеров/конкурентов; военная тема без жалости и героизации. CTA — только «Подпишись, чтобы не потерять».
- [ ] Все цифры — из источника.
- [ ] 🔴 **Ссылки:** при `external_links_allowed: false` (Ward) — ни одного URL. Если ссылки разрешены: пост называет конкретный инструмент/статью — ссылка есть; не называет — ссылки нет. См. `threads_native.md`.
- [ ] 🔴 **Реактивные зачины:** не больше 1-2 на набор (иначе новый шаблон). Нет выдуманных «говорил со знакомым».
