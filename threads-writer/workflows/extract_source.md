# Workflow — Извлечение сути из источника

Один воркфлоу для всех типов входа. Цель — собрать **«банк сырья»**: список тезисов + список проверенных фактов с цифрами.

---

## Тип A. Текст / тезисы / черновик / подборка новостей

1. Прочитать целиком.
2. Выписать:
   - **главные мысли** (1 строка каждая);
   - **факты с цифрами** + источник (если указан);
   - **конфликты / парадоксы** (две правды);
   - **неожиданные углы** (то, что цепляет внимание).
3. Каждая мысль = потенциальный пост.

🔴 **Контекст путешествует с фактом.** Никогда не выписывай число/факт как осиротевший осколок — всегда вместе с его субъектом (кто/что) и что оно измеряет. Иначе в посте получится сирота вроде «−46%» или «$60 млрд» без хозяина (см. `knowledge/standalone_context.md`).
- ❌ «−5%, −13%, −46%»
- ✅ «выручка [компании] по годам: −5%, −13%, −46%»
- ❌ «сделка на $60 млрд»
- ✅ «[компания] купила [стартап] за $60 млрд, чтобы [зачем]»
- ❌ «это видео делалось дешевле»
- ✅ «ролик [что в кадре / какого бренда] год назад требовал студии»

Каждый пункт банка должен быть понятен сам по себе, без открытия источника. Если из источника нельзя вытащить субъект для факта — этот факт **не годится в пост** (его нечем заякорить).

## Тип B. Ссылка на статью / новость

1. **WebFetch** с промптом: «вытащи ключевые тезисы, все цифры с источниками, цитаты, неожиданные факты».
2. Если страница за пейволлом / редирект — сообщить пользователю, попросить вставить текст вручную.
3. Дальше — как тип A.

## Тип C. YouTube / Reels / TikTok / любое видео

Apple Silicon (M-чипы), рабочий путь через `uvx` (без локальной установки):

```bash
# 1. Скачать аудиодорожку
yt-dlp -x --audio-format mp3 -o "/tmp/tw_src.%(ext)s" "<URL>"

# 2. Транскрипция через mlx-whisper (быстрый на M-чипах)
uvx --python 3.12 --from mlx-whisper mlx_whisper /tmp/tw_src.mp3 \
  --model mlx-community/whisper-small-mlx \
  --language ru \
  --output-dir /tmp \
  --output-format txt
```

Если `yt-dlp` / `uvx` отсутствуют — предложить пользователю поставить, либо делегировать в `content-factory`.

Из транскрипта выписать тезисы и факты как в типе A.

## Тип D. Аудио / голосовое (локальный файл)

1. **Конвертация в mp3** (если не mp3):
   ```bash
   ffmpeg -i "<input>" -ar 16000 -ac 1 /tmp/tw_src.mp3 -y
   ```
   `-ar 16000 -ac 1` = моно 16кГц, оптимально для whisper.

2. **Транскрипция** (та же команда `uvx mlx_whisper`, что в типе C).

3. Дальше — как тип A.

---

## Выход воркфлоу

После извлечения собрать:

```
БАНК СЫРЬЯ
─ Тезисы:
  • <мысль 1>
  • <мысль 2>
  • …

─ Факты с цифрами (каждый с субъектом — кто/что и что измеряет):
  • <субъект> <что измеряет> = <цифра> — <источник>
  • …

─ Конфликты / парадоксы:
  • <X vs Y>
  • …

─ Неожиданные углы:
  • <…>
```

Дальше посты лепятся **только** из этого банка (см. `knowledge/fact_check.md` — цифры только из источника).

## 🔴 Сколько постов вытягивает источник (адаптивное количество)

После сборки банка — оценить, **сколько по-настоящему самодостаточных, различных углов** в нём есть. Это и есть число постов (до потолка), а не фиксированные 8.

- **Короткая новость / один факт** → обычно 2–3 самодостаточных угла. Потолок 3.
- **Видео / лонгрид / богатый источник** → до 5 углов. Потолок 5.

Не «нарезать» источник на больше осколков, чем в нём есть самостоятельных мыслей — каждый лишний пост будет сиротой (см. `knowledge/standalone_context.md`). Лучше меньше, но сильных.
