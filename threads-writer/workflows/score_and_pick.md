# Workflow — Скоринг и отбор

## Принцип

**Лучше меньше, но сильных.** Сгенерировать черновиков с небольшим запасом (×1.3 от потолка — не больше, перепроизводство дробит источник на осколки). Каждый прогнать через гейт источника-сироты, потом скоринг, отдать только прошедшее.

🔴 **Количество = ПОТОЛОК, а не квота.** Отдаём столько самодостаточных постов, сколько реально вытянул источник: короткая новость → 2–3, видео/лонгрид → до 5 (см. `config/settings.yml`). **Запрещено добивать набор слабыми постами ради числа** («drop, don't pad»). Если из юнита вышло 3 сильных — отдаём 3, а не растягиваем до 8.

## 🔴 Гейт источника-сироты (ДО скоринга, блокирующий)

Прежде чем считать баллы — прогнать каждый черновик через 3 теста из `knowledge/standalone_context.md`:

1. **Названный субъект** — назван ли словами конкретный субъект (кто/что), или есть `это / его / тот / эту сделку / это видео` в пустоту?
2. **Заякоренное число** — у каждой цифры/%/$ в посте есть «чьё это и что измеряет»?
3. **Своя завязка** — панч приземляется внутри поста, или ждёт невидимую статью?

Хоть один «нет» → **чинить-или-выкинуть:**
- Сначала **починить контекстом**: назвать субъект / приклеить число к подлежащему / добавить строку сетапа — беря сущности и цифры **только из источника** (`fact_check.md`).
- Если осколок в принципе нельзя сделать самодостаточным без копипасты пол-статьи — **выкинуть, не отдавать.** Не растягивать пост на 7 строк ради контекста.

Провал гейта = **veto**: пост не идёт в скоринг вообще, пока не починен. Это сильнее любой суммы баллов.

## Шкала оценки (1–5 по каждой оси)

| Ось | Что измеряем |
|---|---|
| **Хук** | Останавливает ли первая строка скролл? |
| **Напряжение** | Есть ли эмоция / залипание / curiosity gap? |
| **Ясность** | Понятно ли холодному читателю с нуля? (см. `knowledge/cold_reader.md`) |
| **Голос** | Звучит как автор или как «обобщённый ИИ»? (см. `knowledge/voice.md`) |
| **🆕 Reply-bait** | Есть ли в посте зацепка для ответа в коммент? (см. `knowledge/threads_native.md`) |
| **🔴 Shuffle-safety** | Сработает ли пост в одиночку, в рандомной ленте, без собратьев? (см. `knowledge/atomic_posts.md`) |

Максимум — 30 баллов (6 осей × 5). Минимум для отбора — **18**. Veto (бракуют независимо от суммы): пост, не прошедший **гейт источника-сироты** (см. выше); пост с **Shuffle-safety = 1–2** (опирается на соседей).

## Алгоритм

1. **Гейт источника-сироты** (см. выше) — починить или выкинуть сирот. ДО скоринга.
2. После two-pass humanize (см. `workflows/two_pass_humanize.md`) — оценить каждый выживший пост по 6 осям.
3. Сложить → сумма от 6 до 30.
4. Посты со суммой <18 или с veto (источник-сирота / shuffle-safety ≤2) — выкинуть.
5. Отобрать **до потолка** (короткая новость → 2–3, видео/лонгрид → до 5; `config/settings.yml`). 🔴 Если прошедших меньше потолка — **отдать меньше, не добивать слабыми** («drop, don't pad»).
6. **Anti-template check** (см. ниже) — убедиться, что в финальном наборе разные структуры.
7. **Reply-bait final pass** — каждому посту в финале задать вопрос «что захочется ответить?».

## Что показывать пользователю

- По умолчанию — **только финальный отобранный набор**, в порядке убывания силы.
- Никаких «вот черновики, выбирай» — пользователь нанимает нас именно за отбор.

## Когда показать «изнанку»

Если пользователь явно просит:
- «дай несколько вариантов одного поста» → показать 2–3 версии лучшего поста;
- «покажи, что отбраковал» → показать отбракованные с пометкой почему;
- «дай 5 вариантов хука» → 5 первых строк одного типа поста.

## 🔴 Anti-template variety check (от 2 постов, не от 8)

Раньше срабатывало на «8+ постов». **Теперь — от 2.** В Pool-режиме посты одного юнита публикуются вперемешку, и два близнеца из одного источника в ленте палят шаблон сразу. Полная матрица осей — `knowledge/atomic_posts.md`. Минимум проверять:

1. **Разные типы хуков** (см. `knowledge/hook_bank.md`) — не больше **1 повтора** типа на юнит. Микс: curiosity gap / контрарность / тревога / узнавание / личная история / конфликт / список.
2. **Разная синтаксическая структура первой строки.** Не все с «X — это не Y», не все с цифры, не все с вопроса, не все с «я».
3. **Разная длина — мандат.** Из N постов **минимум треть — ultra-short** (1–2 строки). Не все standard.
4. **Разная атрибуция к источнику.** 🔴 **≤ трети** постов одного юнита называют источник (имя/название). Остальные — авторский тезис без ссылки. Иначе все посты кластеризуются вокруг одного имени.
5. **Разный регистр.** Микс обычного и lowercase (rough), но lowercase не на все и не на посты с цифрами.
6. **Разный ритм финала.** Не каждый пост заканчивать вопросом. Чередовать: вопрос / спорный тезис / открытая петля / признание.

Если два поста совпадают по 4+ осям — близнецы, переписать один.

## 🔴 Shuffle-safety final pass

Перед сдачей каждый пост прогнать через 3 вопроса (`knowledge/atomic_posts.md`):

1. **Одиночество** — самоценен сам по себе, без собратьев?
2. **Связки треда** — нет ли «сдвиг, который» / «и вот в чём» / «как писал выше» / нумерации-серии? (бан-лист в `atomic_posts.md`). Найдено — удалить.
3. **Соседство** — если два поста юнита встанут рядом, выглядят как разные мысли или как «части одного»?

Не прошёл — переписать пост, не «подшлифовать».

## 🆕 Reply-bait final pass

Перед сдачей пройти по каждому посту с вопросом:

> **«Что захочется ответить, прочитав это?»**

Если ответа нет — пост слабый для Threads (алгоритм ранжирует по reply-velocity). Варианты починки:

1. Добавить прямой вопрос в конце.
2. Заменить нейтральный тезис на спорный.
3. Добавить личный угол («у меня это работало вот так»).
4. Выкинуть из набора и заменить более «разговорным».

Полное обоснование — `knowledge/threads_native.md`.
