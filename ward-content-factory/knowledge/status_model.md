# Статусная модель единицы контента

Единица контента = **пуля**: одна мысль (одна строка «Единиц контента»), которая разворачивается в несколько форматов (видео-аватар, Threads, карусель). Статус ведётся **на уровне пули**; каждый формат под площадку — строка в «Адаптациях» со своим статусом.

Порядок (движок `scripts/factory.py` не даёт перепрыгнуть шаг без `--force`):

```
Идея → Пуля → Тексты готовы → Медиа готовы → На проверке → Запланировано → Опубликовано
                              (с любого шага) → Отклонено
```

## Что значит каждый статус, кто двигает, какие поля меняются

| Статус | Условие входа (что должно быть заполнено) | Кто делает следующий шаг | Поля «Единиц контента» | «Адаптации» |
|---|---|---|---|---|
| **Идея** | `Пуля` (черновая формулировка), `Инсайт / боль` или источник (ссылка на новость в `Источник в ДНК` / `Материалы`), `Приоритет` | субагент «оформить пулю» (`templates/brief_bullet.md`) | создаются: `№`, `Пуля`, `Инсайт / боль`, `Источник в ДНК`, `Материалы`, `Приоритет`, `Статус=Идея` | — |
| **Пуля** | + `Сегмент ДНК`, `Этап воронки`, `Ступень Ханта`, `Формула хука`, `Хук A/B/C`, `Тезисы тела`, `Доказательство в кадре`, `Формат`, `CTA`, `Красные линии / проверить`, `Аватар` (если в формате есть AI-аватар) | исполнители текстов: eman-scenario, threads-writer, carousel (только текст) | всё перечисленное; `Статус=Пуля` | — |
| **Тексты готовы** | по каждому формату из `Формат` заполнена ячейка: AI-аватар → `Сценарий HeyGen`; Threads → `Threads-посты`; Карусель → `Текст карусели`. Ячейки по стандарту `cell_format_standard.md` | медиа: HeyGen (видео), carousel (рендер), Higgsfield (обложки) | ячейки текстов; `Статус=Тексты готовы` | создаётся строка на каждый формат: `Название` «П-NN · формат», `Формат`, `Площадки`, `Хук`, `Сценарий / текст`, `Подпись к публикации`, `Пуля` (связь), `Статус=Черновик` |
| **Медиа готовы** | у каждой адаптации, которой нужно медиа, есть файлы: видео HeyGen (mp4), слайды карусели (png/mp4), обложка. Threads медиа не требует | оркестратор: QC-гейт | `Папка с медиа` (локальный путь к папке «П-NN …»); `Статус=Медиа готовы` | `Файлы` (путь/имена), `Визуал / B-roll` (если меняли), `Статус=Готово к продакшну` → `Готово` |
| **На проверке** | `factory.py qc --unit N` без 🔴 | человек: «ок» / правки | `QC-отчёт` (вывод движка + решение по 🟡); `Статус=На проверке` | `Статус=На согласовании` |
| **Запланировано** | «ок» человека получено; zernio-posting поставил публикации в расписание | zernio-posting (сам выпускает в нужное время) | `Статус=Запланировано` | `Дата публикации` (план), `Заметки` += ID поста Zernio, `Статус=Запланировано` (если вариант добавлен; иначе `Готово`) |
| **Опубликовано** | все адаптации пули вышли | — (дальше — аналитика) | `Статус=Опубликовано` | `Ссылка на публикацию`, `Дата публикации` (факт), `Статус=Опубликовано`; позже `Просмотры` |
| **Отклонено** | человек или QC решили не делать | — | `Статус=Отклонено`; причина дописывается в `Красные линии / проверить` строкой `[Отклонено] …` (`--note`) | адаптации — не трогаем, редактор удаляет вручную, если нужно |

## Правила переходов

- **Пуля частично готова** (например, Threads есть, а карусель нет) — статус не повышаем. Статус = самый отстающий формат.
- **Threads-only пуля** проходит «Медиа готовы» сразу после текстов (медиа не нужно) — движок не требует файлов, оркестратор переводит статус вручную, отметив «медиа не требуется».
- **Возврат назад.** QC нашёл 🔴 в тексте → статус возвращаем на «Пуля» (`--force`), ячейку переписывает исполнитель. Правки по медиа → на «Тексты готовы».
- **Публикация частями.** Если часть адаптаций уже вышла, а часть запланирована — пуля остаётся «Запланировано» до выхода последней.
- **Старые статусы базы** (`В работе`, `Готово`) движок читает как «Пуля» и «Тексты готовы». Перевести базу на модель: `factory.py infer` (предпросмотр) → «ок» человека → `factory.py infer --apply`.
