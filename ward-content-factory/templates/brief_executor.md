# Шаблон брифа субагента-исполнителя

Подставь `<…>` и отправь как `prompt` инструмента Agent. Один бриф = одна пачка (карусель — всегда одна). Не добавляй историю диалога и соседние пули. Пути — относительно папки `ward-skills/` (подставь абсолютный путь на машине, где идёт работа).

---

## Общая часть (всегда)

```
Ты — исполнитель контент-завода Ward. Твой скилл: <имя скилла> (папка <путь к ward-skills>/<папка скилла>/).

ШАГ 0 — ОБЯЗАТЕЛЬНОЕ ЧТЕНИЕ (до любой работы):
1. Прочитай <папка скилла>/SKILL.md ЦЕЛИКОМ.
2. Прочитай ВСЕ модули, на которые ссылается его карта-роутинг и жёсткие правила
   (knowledge/, workflows/, templates/, materials/ — каждый упомянутый файл, не только оглавление).
   Модули про то, чего в этой задаче нет (например, видео-фоны, если задача только текст), можно пропустить — но назови их.
3. Прочитай <путь к ward-skills>/_ward/Голос бренда Ward (ToV).md и
   <путь к ward-skills>/_ward/ДНК клиента — новички.md (разделы про сегменты пули: <сегменты>).
4. Для визуальных задач — ещё <путь к ward-skills>/_ward/Дизайн-код Ward.md.

ЗАДАЧА: <что сделать — см. блок исполнителя ниже>

ДАННЫЕ ПУЛИ (из Teable, только эта пуля):
№<N> · Пуля: <…>
Сегмент ДНК: <…> · Этап воронки: <…> · Ступень Ханта: <…>
Инсайт / боль: <…>
Формула хука: <…> · Хук A: <…> · Хук B: <…> · Хук C: <…>
Тезисы тела: <…>
Доказательство в кадре: <…>
CTA: Подпишись, чтобы не потерять
Красные линии / проверить: <…>
<Аватар: … — для eman-scenario>
<Материалы / источник: … — если есть>

ФОРМАТ СДАЧИ: строго по стандарту ячеек (ниже — эталон). Блок «═══ ИНСТРУКЦИЯ ═══», контент между маркерами ▼ … ▲, служебные строки вне маркеров.
<вставь соответствующий раздел из knowledge/cell_format_standard.md>

Ничего не публикуй, не пиши в Teable, не устанавливай. Результат положи в файл <путь к папке пули>/texts/<имя>.txt и верни путь.

ОТЧЁТ (обязателен, без него результат не принимается):
1. ПРОЧИТАНО: список файлов, которые ты прочитал полностью.
2. ПРАВИЛА: какие жёсткие правила скилла применил — номер + суть в 3–6 слов; где отступил и почему.
3. КРАСНЫЕ ЛИНИИ: проверил — суммы-обещания / «заработок, доход, быстрые деньги» / биржи и брокеры / ссылки / рубли / «Подпишись, чтобы не потерять» / дисклеймер. Что нашёл и исправил.
4. РЕЗУЛЬТАТ: путь к файлу.
```

## Блок: eman-scenario (сценарий HeyGen)

```
ЗАДАЧА: сценарий короткого вертикального ролика (Shorts / Reels / TikTok, 30–60 сек) для AI-аватара HeyGen по пуле.
Аватар: <имя пресета> — роль, голос, манера: <скопируй блок из knowledge/avatar_presets.md>.
Режим голоса скилла: heygen_avatar (без тире, числа словами, без скобок и эмодзи).
Сдача — ячейка «Сценарий HeyGen»: озвучка между «▼ ТЕКСТ ДЛЯ ОЗВУЧКИ ▼ / ▲ КОНЕЦ ТЕКСТА ▲», в конце озвучки — «Подпишись, чтобы не потерять»;
ниже «─── ДЛЯ МОНТАЖА ───»: таймкоды и визуал, текст-хук на экране, подпись к публикации (с призывом и «Не финансовая рекомендация»), субтитры, каркас, «Проверить/подставить».
Файл: texts/heygen.txt
```

## Блок: threads-writer (посты Threads)

```
ЗАДАЧА: 2–4 ОТДЕЛЬНЫХ поста Threads по пуле (Pool-режим, не тред), каждый ≤ 500 символов, с reply-bait.
Количество — адаптивно: лучше 2 сильных, чем 4 средних. Дисклеймер в пост не вставлять (он в профиле).
Сдача — ячейка «Threads-посты»: «▼ ПОСТ k из N ▼ … ▲ КОНЕЦ ПОСТА k ▲» + служебная строка (Символов · Тип · Режим · Скоринг · Зачем).
Файл: texts/threads.txt
```

## Блок: carousel — текст

```
ЗАДАЧА: текст ОДНОЙ карусели Instagram по пуле, максимум 10 слайдов (9 контентных + финальный «Подпишись, чтобы не потерять»).
Только текст и подсказки визуала — рендер не делать.
Сдача — ячейка «Текст карусели»: «▼ СЛАЙД k из N ▼ Заголовок / Текст / Визуал ▲» + «═══ ПОДПИСЬ К ПОСТУ ═══ … ═══ КОНЕЦ ═══» (с призывом и «Не финансовая рекомендация», без хэштегов).
Файл: texts/carousel.txt
```

```
Визуал — строго по <путь>/_ward/Дизайн-код Ward.md (палитра, Montserrat, скругления, «чего нельзя»). Логотип — из файла в _ward/логотип/, не генерировать.

```
