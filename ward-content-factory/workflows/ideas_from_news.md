# Workflow — «Новые идеи из новостей»

**Вход:** «новые идеи из новостей», «что свежего для контента».
**Итог:** утверждённые новости parsing-ward превращены в пули со статусом «Идея» в «Единицах контента». parsing-ward работает по своему расписанию — оркестратор его **не запускает** и **не пишет** в его таблицы.

## Шаг 1 — откуда читать

ID таблицы «Отобранные новости»: `config/settings.yml → teable.news_selected`; если там заглушка — `../parsing-ward/config/settings.yml → teable.tables.selected`. Если таблица в другой базе / другом сервере Teable — адрес и токен берутся оттуда же (`../parsing-ward/config/`), иначе — сообщить человеку, что parsing-ward не настроен.

Чтение — постранично (100 за запрос):
```
GET {api_url}/table/{news_selected}/record?fieldKeyType=name&take=100&skip=0
```

## Шаг 2 — что брать

1. По умолчанию — строки со **Статус = «Утверждено»** (их утвердил редактор).
2. Если человек сказал «бери всё свежее» — ещё «Новое» с оценкой ≥ `scoring.write_threshold` parsing-ward (7).
3. Не брать новость, если пуля по ней уже есть: ссылка новости уже стоит в «Материалы» какой-то пули (проверить через `factory.py list` + `show`, или сравнить ссылки из всех пуль).
4. Не брать, если тема повторяет пулю последних 2 недель (сравнить смысл «Пуля»).

Схема полей «Отобранных новостей» — `../parsing-ward/knowledge/pipeline_architecture.md` (название, суть, ссылка на источник, оценка, рекомендация форматов).

## Шаг 3 — создать идеи

Для каждой новости — JSON по образцу `templates/unit_idea.example.json` и:
```bash
python3 scripts/factory.py add --json <файл>
```
Поля: `Пуля` — черновая мысль одной фразой (не заголовок новости, а вывод для новичка: «что это значит для тебя»), `Инсайт / боль` — суть новости + почему важно сегменту, `Материалы` — ссылка на источник, `Источник в ДНК` — «новость parsing-ward от <дата>», `Приоритет` — 🔥 если новость горячая (≤ 48 ч, ликвидации, решения регуляторов), `Статус` — «Идея», `№` — движок поставит сам.

🔴 Оркестратор пишет только черновую формулировку и суть из таблицы новостей — не хуки, не тексты. Оформление в пулю — субагент «пуля» на следующем шаге.

## Шаг 4 — отчёт

```
Из новостей: найдено N утверждённых, создано K идей (№… – №…), пропущено M (уже есть / повтор темы)
Дальше: «доведи пулю №…» или «сделай контент на неделю»
```

Статус в таблице parsing-ward не меняем. Если редактору удобнее, чтобы взятые новости помечались, — это настраивается в parsing-ward, не здесь.
