# Workflow — Как запускать исполнителей

Общий порядок для любого шага конвейера, где работает исполнитель. Кто что делает — `knowledge/executors.md`.

## 1. Собрать задание

Для каждой пули — данные из Teable: `python3 scripts/factory.py show N`. В бриф кладём **только поля этой пули** (не всю таблицу и не соседей).

## 2. Нарезать пачки

| Исполнитель | Пачка |
|---|---|
| Субагент «пуля» | до 5 идей в одном агенте |
| eman-scenario, threads-writer | `pipeline.texts_batch_size` пуль (по умолчанию 5) |
| carousel (текст и рендер) | 🔴 строго 1 карусель = 1 агент |
| HeyGen, Higgsfield | не субагенты — оркестратор вызывает сам (`workflows/media.md`), по одному |
| zernio-posting | 1 адаптация = 1 вызов; можно одним агентом пачку по готовому плану, если план утверждён |

## 3. Запустить

**Субагенты (по умолчанию, везде).** Инструмент Agent, бриф — `templates/brief_executor.md` с подставленными полями. Независимые агенты запускай **параллельно, одним сообщением** (несколько вызовов Agent сразу): например, 2 агента eman-scenario + 2 threads-writer + 5 carousel. Рендер каруселей и генерация медиа — последовательно (тяжёлые процессы и лимиты API).

**Отдельные чаты (только Claude Desktop, опционально).** Если `pipeline.use_desktop_sessions`:
- `no` — только субагенты;
- `ask` — перед тяжёлым этапом (рендер 3+ каруселей, пачка видео) спроси: «Вынести рендер каруселей в отдельный чат, чтобы следить за ним отдельно?»;
- `yes` — выносить без вопроса.
В отдельный чат уходит тот же бриф + строка «по завершении запиши результат в файлы <папка пули> и сообщи пути». Ты не опрашиваешь его — дождись отчёта. В Claude Code CLI такого инструмента нет → всегда субагенты.

## 4. Принять

По каждому результату:
1. Есть отчёт о прочитанных файлах и применённых правилах? Нет → перезапуск (см. `knowledge/executors.md` → «Приёмка»).
2. Формат ячейки по `knowledge/cell_format_standard.md`? Нет → вернуть.
3. Сохранить в файл пули и прогнать `factory.py qc --file … --kind …`. 🔴 → вернуть исполнителю с выводом QC, не править самому. Не больше 2 возвратов на одну пулю — потом показать человеку.
4. Записать: `factory.py set N --field "<поле>" --file <файл>`; создать адаптации (`knowledge/status_model.md` → «Тексты готовы»).
5. Когда все нужные форматы пули готовы — `factory.py status N "<следующий статус>"`.

## 5. Отчитаться человеку

Коротко: сколько пуль перешли, какие вернулись и почему, что ждёт его решения. Без пересказа текстов — тексты в Teable.
