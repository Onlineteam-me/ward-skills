# Workflow — Мастер настройки («настрой завод»)

**Когда:** первый запуск; команда «настрой завод» / «проверь подключения»; любой шаг упал с ошибкой доступа.
**Итог:** человек получает список «✅ работает / ❌ чего не хватает и где это взять», а все заглушки `{{...}}` в `config/settings.yml` заменены.

🔴 Ключи в чат не просим и не печатаем. Человек сам вписывает их в `config/secrets.yml`. Если человек всё же прислал ключ в чат — записать его в `secrets.yml`, в ответе не повторять, посоветовать перевыпустить.

---

## Шаг 0 — файлы на месте

1. Есть ли `config/secrets.yml`? Нет → скопировать из образца:
   ```bash
   cp config/secrets.example.yml config/secrets.yml
   ```
   и попросить человека вписать ключи (где взять — комментарии в файле).
2. Рядом лежат соседние скиллы (`../threads-writer`, `../eman-scenario`, `../carousel`, `../zernio-posting`, `../parsing-ward`, `../_ward`)? Это проверит шаг 1.

## Шаг 1 — автоматическая проверка

```bash
python3 scripts/factory.py check
```

Скрипт проходит блоки: заглушки в настройках → ключи → Teable → Zernio → HeyGen → исполнители. Покажи человеку вывод сжато, сгруппировав по «что сделать».

## Шаг 2 — Teable

| Что | Где взять | Куда вписать |
|---|---|---|
| Адрес API | адрес сервера + `/api` (облако — `https://app.teable.ai/api`) | `teable.api_url` |
| Токен | Teable → аватар → Personal access token; доступ к базе завода, права на записи и поля | `secrets.yml → teable.api_token` |
| ID базы | адресная строка базы: `…/base/bse…` | `teable.base_id` |
| ID 4 таблиц | `check` сам напечатает «Таблицы в базе: имя = tbl…», когда ID — заглушки | `teable.tables.units / adaptations / research / accounts` |

После заполнения повтори `check`. Дальше он проверит поля (`knowledge/teable_schema.md`):

- **❌ «units.Статус: не хватает вариантов»** — в базе старые варианты (Идея / В работе / Готово). Предложи человеку: «Добавить в поле Статус варианты Пуля, Тексты готовы, Медиа готовы, На проверке, Запланировано, Опубликовано, Отклонено? Старые варианты не удаляю». После «ок» — добавить (Teable → поле → изменить, или API `PATCH /table/{id}/field/{fieldId}` с полным списком choices: старые + новые).
- Потом перевести существующие пули на модель: `python3 scripts/factory.py infer` (предпросмотр) → показать → «ок» → `python3 scripts/factory.py infer --apply`.
- **⚠️ рекомендуемые поля** «Аватар» (один выбор: Бабушка у Ламбо / Подкастер / Девушка в кафе / Ретро-трейдер), «Папка с медиа» (однострочный), «QC-отчёт» (длинный текст) — предложить добавить, после «ок» создать.
- **⚠️ «adaptations.Статус: Запланировано»** — предложить добавить вариант.
- 🔴 Порядок колонок и виды таблиц не трогать.

Лимит Teable — **100 записей за запрос**; движок читает постранично, руками в запросах `take` больше 100 не ставить.

## Шаг 3 — Zernio

| Что | Где взять | Куда |
|---|---|---|
| API-ключ | zernio.com → Settings → API Keys | `secrets.yml → zernio.api_key` |
| ID профиля | Zernio → Profiles | `zernio.profile_id` |
| accountId Instagram / Threads / TikTok / (YouTube) | `check` напечатает «Доступные: платформа @ник = id», когда ID — заглушки; либо MCP Zernio `accounts_list` | `zernio.accounts.*` |

Если в Zernio не подключена площадка (нет TikTok в списке) — человеку подключить её в кабинете Zernio, потом повторить `check`.
zernio-posting имеет свой `config.yaml` — значения Teable/Zernio там должны совпадать с этими (мастер сверяет глазами и подсказывает). Для работы в связке с заводом в `../zernio-posting/config.yaml` поставить `teable.content_unit_ready_status: "На проверке"` — это делает человек или исполнитель zernio-posting, оркестратор чужие конфиги не правит.

## Шаг 4 — Higgsfield (MCP)

Скрипт это не проверит — проверяешь ты в Claude:
1. Найди инструменты Higgsfield: поиск инструментов по слову `higgsfield` (в Claude Code — ToolSearch). Есть инструменты вида `…higgsfield…generate…` → MCP подключён.
2. Сделай лёгкий запрос без генерации (баланс / список моделей / история), если такой инструмент есть.
3. Нет инструментов → ❌ «Higgsfield не подключён: Claude → Настройки → Connectors (или `claude mcp add`) → добавить Higgsfield MCP и войти в аккаунт». Ключ хранится в настройках Claude, не в `secrets.yml`.
4. Требует входа (OAuth) → сказать человеку пройти вход; сам ты код/токен не запрашиваешь.

## Шаг 5 — HeyGen

| Что | Где взять | Куда |
|---|---|---|
| API-ключ | app.heygen.com → Settings → API | `secrets.yml → heygen.api_key` |
| ID 4 аватаров | HeyGen → Avatars → аватар → ID (фото-аватары создаются из портретов `materials/avatars/`) | `heygen.avatars.<ключ>.avatar_id` |
| Тип аватара | фото-аватар = `talking_photo`, студийный = `avatar` | `heygen.avatars.<ключ>.avatar_type` |
| ID голосов | HeyGen → Voices → голос → ID (подбор — по описанию голоса в `knowledge/avatar_presets.md`) | `heygen.avatars.<ключ>.voice_id` |

`check` проверит ключ (остаток квоты) и что каждый avatar_id есть в аккаунте. Если аватаров ещё нет — завод работает без видео: пули с форматом «AI-аватар» дойдут до «Тексты готовы» и остановятся, это нормально.

## Шаг 6 — хранилище и итог

1. `storage.media_root` — абсолютный путь к папке, где будут папки пуль «П-NN …» (видео, слайды, обложки). Создать, если нет.
2. Финальный `check` → `ИТОГ: ✅ завод готов`.
3. Ответ человеку — по шаблону:

```
Завод: <готов / готов частично>
✅ Работает: Teable (4 таблицы), Zernio (Instagram, Threads), Higgsfield, исполнители
❌ Не хватает: <пункт → что сделать → где взять>
⚠️ Рекомендую: <поля / варианты статусов> — добавить? (да/нет)
Дальше: «новые идеи из новостей» или «сделай контент на неделю».
```
