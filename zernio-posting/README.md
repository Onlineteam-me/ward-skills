# zernio-posting — публикация контента Ward

Скилл для Claude Code: публикует готовый контент Ward (Instagram-карусели и Reels, Threads-посты) через **Zernio MCP**, перед выходом проверяет подпись на голос бренда, складывает исходники в локальный архив и отмечает результат в **Teable**.

Контент скилл не создаёт — его делают `carousel`, `threads-writer`, `parsing-ward`. Этот скилл — последний шаг: «выложить и отметить».

## Что делает

1. Берёт исходник: локальную папку со слайдами/видео или строку из Teable.
2. Проверяет подпись по чек-листу Ward (`knowledge/ward_brand_check.md`): призыв «Подпишись, чтобы не потерять», дисклеймер «Не финансовая рекомендация», никаких обещаний заработка, ссылок и названий бирж.
3. Публикует или ставит в расписание через Zernio в Instagram / Threads.
4. Переносит папку в локальный архив `<archive_root>/{Карусели|Рилсы|Тредс-посты}/`.
5. Пишет статус и ссылки на посты в Teable.

## Установка

```bash
# вариант 1 — скопировать
cp -R zernio-posting ~/.claude/skills/zernio-posting

# вариант 2 — симлинк (удобно, если пакет лежит в рабочей папке)
ln -s "/путь/к/ward-skills/zernio-posting" ~/.claude/skills/zernio-posting
```

Нужно на компьютере:
- **Zernio MCP**, подключённый к Claude (`https://mcp.zernio.com/mcp`), с привязанными аккаунтами Instagram и Threads Ward;
- `python3` с библиотекой `requests` (для пакетной загрузки каруселей);
- `ffmpeg` (сжатие видео больше 4 МБ);
- `curl`, `jq`.

## Настройка перед первым запуском

### 1. Ключи — `config/secrets.yml`

```bash
cp config/secrets.example.yml config/secrets.yml
```

Вписать `zernio_api_key` (Zernio → Settings → API) и `teable_api_token` (Teable → Personal access token с доступом к базе Ward). Файл `secrets.yml` никому не пересылать и не коммитить. Можно вместо файла задать переменные окружения `ZERNIO_API_KEY` и `TEABLE_API_TOKEN`.

### 2. Заглушки `{{...}}` в `config.yaml`

| Заглушка | Где взять |
|---|---|
| `{{ZERNIO_PROFILE_ID}}` | Zernio → профиль, или MCP `profiles_list` |
| `{{INSTAGRAM_USERNAME}}`, `{{THREADS_USERNAME}}` | ники аккаунтов Ward без `@` |
| `{{ZERNIO_ACCOUNT_ID_INSTAGRAM}}`, `{{ZERNIO_ACCOUNT_ID_THREADS}}` | попросить Claude вызвать `accounts_list` в Zernio MCP |
| `{{TEABLE_URL}}` | адрес Teable, например `https://app.teable.ai` |
| `{{TEABLE_BASE_ID}}` | из адреса базы: `.../base/<вот это>/...` |
| `{{TABLE_PUBLICATIONS}}`, `{{TABLE_CONTENT_UNITS}}`, `{{TABLE_CHANNELS}}` | из адреса таблицы: `.../table/<вот это>` |
| `{{FLD_...}}` | ID полей: Teable → поле → «Редактировать» → ID, или API `GET /api/table/<id>/field` |
| `{{ARCHIVE_ROOT}}` | папка локального архива опубликованного, например `~/Ward/Контент завод база контента` |

Пока для шага стоит заглушка, скилл остановится и попросит её заполнить — ничего не опубликует вслепую.

Часовой пояс расписания по умолчанию — `Europe/Kyiv` (`posting.timezone`).

### 3. Как связать с базой Ward в Teable

У Ward в базе на app.teable.ai уже есть две таблицы, которые подходят скиллу.

**«Единицы контента» → путь B (`unit:<№>`, «опубликуй принятые»).** Впишите ID этой таблицы в `teable.tables.content_units` и сопоставьте имена полей в `teable.content_unit_field_names`:

| Ключ скилла | Поле в методике | Поле у Ward |
|---|---|---|
| `koncept` | Концепт | **Пуля** |
| `id_number` | ID | **№** |
| `status` | Статус | **Статус** |
| `formaty` | Форматы | **Формат** |
| `podpis_k_karuseli` | Подпись к карусели | **Текст карусели** |
| `tred` | Тред | **Threads-посты** |
| `papka_unit` | Папка с медиа | создать (однострочный текст) |
| `post_insta` | Post Insta | создать (выбор: Опубликован / Не опубликован) |
| `threads_post` | Threads пост | создать (выбор: Опубликован / Не опубликован) |

Статус «можно публиковать» у Ward — «Готово»: поставьте `content_unit_ready_status: "Готово"`. Значение «вернуть на правку» (`content_unit_rework_status`) — то, которое используется в вашей таблице. Поля «Сценарий HeyGen» и прочие сценарии скилл не публикует: видео сначала надо снять или сгенерировать.

**«Адаптации» → путь A (вместо таблицы «Публикации»).** В «Адаптациях» одна строка — один готовый пост под площадку, это та же роль, что у «Публикаций». Впишите ID «Адаптаций» в `teable.tables.publications` и поменяйте имена полей в `workflows/07_update_teable.md` и `templates/teable_publication_row.json`:

| Поле в методике | Поле в «Адаптациях» |
|---|---|
| Тема | Название |
| Формат | Формат (+ «Площадки») |
| Текст | Подпись к публикации |
| Тредс | Сценарий / текст (для форматов Threads-пост / Threads-тред) |
| Статус → «Опубликовано» | Статус → «Опубликовано» (такая опция уже есть) |
| Когда публикуем | Дата публикации |
| Ссылки на публикации | Ссылка на публикацию |
| Папка с медиа | Файлы |

Отдельного «Статуса Threads» в «Адаптациях» нет — там одна строка на одну площадку, поэтому хватает общего «Статуса».

Если не хотите трогать имена в workflows, создайте отдельную таблицу «Публикации» по схеме из `knowledge/teable_schema.md`.

### 4. Папки с медиа

Медиа в пакет не входят. Скилл берёт их из папки, которую вы укажете в команде, из поля «Папка с медиа» в Teable или из `local.source_hints` в `config.yaml`. Пустая или ненайденная папка — это **предупреждение** («нет медиа, пропускаю»), а не падение: скилл спросит путь и не потратит одноразовый токен загрузки.

Раскладка папки с каруселью: `01.jpg … 10.jpg` (или в подпапке `out/`), рядом по желанию `подпись_под_пост.md` и `треды.md`. Reel — одна папка с одним `.mp4`/`.mov` (9:16, до 90 сек, до 4 МБ).

## Примеры команд

```
/zernio-posting ~/Ward/готовые/12_stop_loss_basics
/zernio-posting #rec1234567890
/zernio-posting unit:12
опубликуй принятые
запости карусель про стоп-лосс на завтра в 18:00
```

## Структура

- `SKILL.md` — оркестратор, 9 главных правил, чек-листы
- `config.yaml` — ID, пути, правила (без секретов, с заглушками)
- `config/secrets.example.yml` — образец ключей
- `knowledge/` — правила Zernio, схема Teable, маршрутизация, brand check Ward
- `workflows/` — пошаговые сценарии (`06` удалён намеренно)
- `scripts/` — загрузчики каруселей в Zernio
- `templates/` — шаблон строки Teable и финального отчёта
