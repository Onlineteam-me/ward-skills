# 📲 /zernio-posting — оркестратор постинга

> **Что делает:** забирает локальную папку с медиа (или строку из Teable) → проверяет подпись на голос Ward → публикует в Instagram/Threads через Zernio → архивирует в локальную базу → пишет результат обратно в Teable.

> **Что НЕ делает:** не генерирует контент (для этого — `/carousel`, `/threads-writer`), не редактирует, не сжимает превентивно.

> **Перед первым запуском:** заполнить заглушки `{{...}}` в `config.yaml` и ключи в `config/secrets.yml` (см. `README.md`). Если в `config.yaml` остались заглушки для нужного шага (accountId, ID таблицы) — **остановиться и попросить пользователя их заполнить**, ничего не публиковать.

## 🎯 Карта триггеров

| Триггер | Источник | Что делаю |
|---|---|---|
| `/zernio-posting <путь_к_папке>` | **локальная папка** | Создаю/обновляю строку в **«Публикации»** (`publications`). Публикую. Меняю Статус → «Опубликовано». |
| `/zernio-posting #<row_id>` | строка в **«Публикации»** | Беру строку, беру медиа из attachments / локальной папки. Публикую. Обновляю эту же строку, Статус → «Опубликовано». |
| `/zernio-posting unit:<ID>` или «опубликуй единицу контента <ID>» | строка в **«Единицы контента»** | Беру строку, читаю «Подпись к карусели» (IG) + «Тред» (Threads) + медиа из «Папка с медиа». Публикую. **Per-format статус** в Единице: `Post Insta`=«Опубликован» (если IG) и/или `Threads пост`=«Опубликован» (если Threads). Поле «Статус» НЕ трогаю. **В «Публикации» НЕ создаю запись.** |
| «опубликуй принятые» / `/zernio-posting all-accepted` | **все** «Единицы контента» со Статус = `content_unit_ready_status` где `Post Insta`/`Threads пост` ≠ «Опубликован» | Прохожу пачкой, публикую каждую, ставлю per-format статусы. |
| `/zernio-posting` без аргумента | — | Спрашиваю: «папка / строка Публикаций / Единица контента / все принятые?» |
| «запости / опубликуй / выложи …» | по контексту | То же что `/zernio-posting`. |

> Имена полей и таблиц выше — из методики. Реальные имена в вашей базе задаются в `config.yaml → teable.content_unit_field_names` (у Ward, например, «Пуля», «№», «Текст карусели», «Threads-посты» — см. `README.md`).

## 🔀 Два независимых пути постинга

**Путь A:** локальная папка / строка в «Публикации» → пост → Статус в «Публикации». Используется для ручных каруселей вне конвейера.

**Путь B (для контент-конвейера):** строка в «Единицы контента» со Статус = `content_unit_ready_status` (по умолчанию «Принято») → пост → **per-format статус** (`Post Insta` / `Threads пост`) = «Опубликован». В «Публикации» запись НЕ создаётся (правило: не дублировать).

🔴 **Жизненный цикл «Единицы контента»:**
- **Статус строки:** «Принято» (готово к публикации, ставит генератор контента) → «На правки» (редактор просит переделать). Никакого «Опубликовано» здесь нет.
- **Per-format статусы:** `Post Insta` (IG) и `Threads пост` (Threads), каждый проходит три стадии:
  1. `null/пусто` (новая строка, ещё не взята в работу)
  2. **«Не опубликован»** — zernio ставит **в момент взятия в работу** (Шаг 2.5 → `workflows/08_path_B_content_units.md`), ДО публикации
  3. **«Опубликован»** — zernio ставит после успешной публикации
- 🔴 **Пустое поле = юнит ещё не взят в работу скиллом.** «Не опубликован» = взят, но не отправлен/запланирован/упал.
- Если в одной строке Формат = Карусель + Тред — публикуется в две платформы, два per-format статуса обновляются независимо.

Связка с генератором контента: скилл `parsing-ward` (если установлен рядом) → `workflows/content_batch.md`, шаг 4.

## 🔴 9 ПРАВИЛ, КОТОРЫЕ НЕЛЬЗЯ НАРУШАТЬ

(полная методология — `knowledge/zernio_rules.md`)

1. **После `409 duplicate` от Zernio — НИКОГДА не retry.** Пост уже создан. Сразу `posts_list`/`posts_get`.
2. **`scheduled_for` в прошлом → публикуется немедленно.** Всегда проверять: время > now + 5 мин.
3. **Instagram карусель = жёстко 10 слайдов через API.** 11+ — только руками в приложении. Threads карусель = 20.
4. **`media_items` ВСЕГДА на top-level запроса**, не внутри `platforms[].customMedia` (иначе UI покажет «Missing media content»).
5. **Поля `platforms[]` — camelCase** (`accountId`, `scheduledFor`, `platformSpecificData`). Snake_case → 400 ошибка.
6. **🔴 Имена MCP-инструментов БЕЗ суффикса `_post`:** `posts_create` (НЕ `posts_create_post`), `posts_list` (НЕ `posts_list_posts`), `posts_get` (НЕ `posts_get_post`). Был факап: 30 мин на поиск несуществующих инструментов.
7. **🔴 После реконнекта MCP инструменты могут не показываться** (300+ tools, лимит Claude). Вызывать напрямую по имени — они работают. Fallback: REST API `zernio.com/api/v1/posts` с Bearer-ключом из `config/secrets.yml → zernio_api_key`.

8. **🔴 Threads-поле = ПАЧКА, не один пост.** Поле «Тред» из «Единиц контента» (или «Тредс» из «Публикаций») может содержать 2-3 отдельных поста, разделённых `———` с маркером `Пост N/TOTAL` перед каждым. Публиковать **по одному** через `posts_create` (в цикле), с задержкой 30 сек между постами. НИКОГДА не публиковать всю пачку одним постом (Threads обрежет по 500 симв., смысл потеряется). Backward compat: если маркеров нет — сплитим только по `———`; если и разделителя нет — один пост. Полный алгоритм — `workflows/02_post_threads.md`.

9. **🔴 ПОСЛЕ ПУБЛИКАЦИИ ЮНИТА → PATCH статуса в Teable (обязательно).**
   Публикация в Zernio (scheduled или published) считается **завершённой ТОЛЬКО ПОСЛЕ** обновления per-format статуса в «Единицах контента»:
   - **Instagram карусель** запланирована/опубликована → `PATCH {{TABLE_CONTENT_UNITS}}/record/{unit_id}` → поле **«Post Insta»** = **«Опубликован»**.
   - **Threads пост** (все 2-3 поста из пачки успешно созданы) → PATCH → поле **«Threads пост»** = **«Опубликован»**.
   - Если из 3 Threads-постов создалось только 2 → **НЕ** ставить «Опубликован», зафиксировать частичный успех в «Комментарий».
   - Статус строки «Статус» НЕ трогать — это отдельное поле.

   **Причина:** без этого юнит в Teable остаётся «Не опубликован», и редактор не видит что уже запланировано → рискует запланировать повторно.
   **Триггер самопроверки:** если после `posts_create` ты НЕ вызвал PATCH — публикация не завершена. Прошёл 200 от Zernio → сразу PATCH.
   **Batch-режим:** после каждого юнита обновляй статус, не откладывай на конец батча (если API упадёт в середине, часть уже помечена, легко возобновить).

## 🔄 Workflow (8 шагов)

```
ROUTE → DETECT → BRAND CHECK → ASK TIMING → POST → CONFIRM → ARCHIVE → UPDATE TEABLE
```

### Шаг 1. ROUTE — определить источник
- Триггер с путём к папке → читаю `ls`, определяю содержимое.
- Триггер с `#row_id` → `GET /api/table/{tableId}/record/{id}` из Teable, читаю поля.
- Без аргумента — спрашиваю.
- Подробности: `workflows/01_route.md`

### Шаг 2. DETECT — что и куда постим
- В папке: `1 mp4` → Reel; `≥2 файла` → Carousel; только `*.md` → Threads-only.
- В строке Teable: смотрю колонку «Формат» (multi-select: «Карусель», «Рилс», «Тредс»).
- Один контент может породить **до 3 публикаций**: IG Carousel + IG Reel + Threads-text — каждая отдельная.
- Подробности: `knowledge/content_routing.md`

### Шаг 3. BRAND CHECK — подпись в голосе Ward
- Прогоняю caption и Threads-тексты по `knowledge/ward_brand_check.md`: призыв «Подпишись, чтобы не потерять», дисклеймер «Не финансовая рекомендация», нет обещаний сумм/гарантий, нет стоп-слов теневого бана, нет внешних ссылок и названий бирж/конкурентов, валюта $ или USDT.
- Нашёл нарушение → **не правлю молча**: показываю пользователю, что именно не так, и предлагаю исправленный вариант. Публикую только после «ок».

### Шаг 4. ASK TIMING — когда публикуем
- **Threads-текст** → по умолчанию `publish_now: true` (если не сказано иначе).
- **IG Carousel/Reel** → спрашиваю слот.
  - Если в строке поле «Когда публикуем» заполнено и в будущем — предлагаю его.
  - Проверяю через `posts_list`, нет ли уже запланированных постов на этом аккаунте в пределах **3 часов** до/после. Если конфликт — предупреждаю и предлагаю свободный слот.
  - Если в строке есть И Carousel И Reel — спрашиваю про каждый отдельно, **никогда не ставлю одновременно**.

> ⚖️ **Default интервал между IG-постами на одном аккаунте: 3 часа.** Меньше — только если пользователь явно попросит.

### Шаг 5. POST — публикуем через Zernio
- Загружаю медиа через **Воркфлоу F** (presigned URL → R2 → publicUrl). См. `knowledge/zernio_rules.md`.
- Для каждой публикации — отдельный вызов `posts_create` с правильной структурой:
  - `media_items` на верхнем уровне (правило 4)
  - `platforms[].accountId` в camelCase (правило 5)
  - Для Reel — `platformSpecificData: {contentType: "reels", shareToFeed: true}`
- При 409 или connection lost — НЕ retry, сразу `posts_list` (правило 1).

### Шаг 6. CONFIRM — дождаться публикации
- Поллим `posts_get` пока `status` ≠ `published`.
- Для каруселей с видео — может занимать 5–15 минут (Meta обрабатывает контейнер).
- Получаем `platformPostUrl` — это финальная ссылка на пост.

### Шаг 7. ARCHIVE — переносим исходник
- **Локально:** `mv` папки в `<config.local.archive_root>/{Карусели|Рилсы|Тредс-посты}/`.
- Облачные диски не используются — только локальное хранение.
- Подробности: `workflows/05_archive_local.md`.

### Шаг 8. UPDATE TEABLE — пишем результат
- Если строка существует (триггер был с `#row_id` или нашлась по теме) → `PATCH`:
  - «Статус» = «Опубликовано» (для IG-публикации)
  - «Статус Threads» = «Опубликовано» (для Threads-публикации)
  - «Ссылки на публикации» += новые URL
  - «Папка с медиа» = **локальный путь** к папке в архиве
  - 🔴 **«Медиа» = аплоад через Teable attachments API** (для каруселей — ОБЯЗАТЕЛЬНО; слайды → `slide_NN.jpg`)
- Если строки нет → `POST` с заполнением всех полей:
  - «Тема», «Статус», «Формат», «Заголовок», «Текст», «Когда публикуем», «Папка с медиа», «Комментарий»
  - 🔴 **После POST сразу же — attachments в «Медиа»** (для каруселей ОБЯЗАТЕЛЬНО; не считать шаг завершённым без загрузки слайдов)
- Подробности: `workflows/07_update_teable.md`.

### Путь B — публикация из «Единицы контента» (полный flow)
Когда триггер `unit:<ID>` или «опубликуй принятые» → `workflows/08_path_B_content_units.md`. Это **отдельный путь**, который НЕ создаёт записей в «Публикации», только меняет per-format статусы в Единицах.

🔴 **Медиа — ТОЛЬКО локально.** Читаю поле «Папка с медиа» как локальный путь. Для архивных записей — ищу в `config.local.archive_root`. Облачные диски не используются — не заливать, не скачивать, не ссылаться.

### Batch-постинг N каруселей

Когда нужно запланировать **пачку** каруселей (например 14 × 2/день из «Единиц контента»):
→ `workflows/09_batch_carousel_upload.md` + `scripts/upload_carousel.py`

**Главное:**
- Pre-flight check ДО получения токенов (пустые папки = сожжённые токены).
- Python uploader, **не bash eval** (ломается на `;type=…`).
- URL для постов — **строго из ответа upload**, никаких ручных копий (был факап: перепутал URL → 400 "Image not found").
- Параллелить токены, uploads и posts_create.
- См. правила 13-17 в `knowledge/zernio_rules.md`.

## 📦 Конфигурация

Все ID и пути — в `config.yaml`. **Секреты (API-ключи/токены) — только в `config/secrets.yml`** (образец — `config/secrets.example.yml`; сам `secrets.yml` никуда не передавать и не коммитить).
**Не хардкодить значения в SKILL.md, workflows или config.yaml!** В примерах запросов в workflows стоят заглушки вида `{{TEABLE_URL}}`, `{{TABLE_CONTENT_UNITS}}` — при выполнении подставлять значения из `config.yaml`.

| Что | Где взять |
|---|---|
| Teable token | `config/secrets.yml` → `teable_api_token` (или env `TEABLE_API_TOKEN`) |
| Zernio API-key | `config/secrets.yml` → `zernio_api_key` (или env `ZERNIO_API_KEY`) |
| Zernio MCP accountId IG/Threads | `config.yaml` → `zernio.accounts.*` |
| Teable URL / base / таблицы / поля | `config.yaml` → `teable.*` |
| Teable schema (поля + статусы + форматы) | `knowledge/teable_schema.md` |
| Голос и красные линии Ward | `knowledge/ward_brand_check.md` |

🔴 Ключи и токены никогда не выводить в чат и не вставлять в файлы скилла.

## 🚨 Когда останавливаюсь и спрашиваю

- В `config.yaml` заглушки вместо accountId / ID таблиц → «заполни config.yaml, без этого не публикую»
- Триггер без аргумента → «папка или строка?»
- Подпись не прошла brand check → показать нарушения и исправленный вариант
- В одной строке несколько форматов → таймслот для каждого отдельно
- В папке 11+ слайдов → «обрезать какой?» или «постим в Threads (там 20 ок)?»
- Конфликт расписания (нашёл запланированный пост в пределах 3 ч) → предложить альтернативный слот
- Видео > 4MB и не из предсжатой CTA-библиотеки → подтвердить сжатие через ffmpeg
- Не нашёл локальную папку / папка пустая → спросить путь (это предупреждение, не падение)
- Уже есть пост с таким же текстом за последние 24h (дедуп) → подтвердить публикацию или переформулировать
