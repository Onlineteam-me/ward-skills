# Workflow 02 — POST THREADS

**Когда:** в строке есть колонка «Тредс»/«Тред» с текстом ИЛИ в локальной папке есть `треды.md`/`threads.md`.

**По умолчанию:** `publish_now: true`. Если пользователь сказал «запланируй на X» — `scheduled_for`.

---

## 🔴 Формат содержимого поля «Тред»

Threads-writer выдаёт **пачку постов** с явной нумерацией и разделителями:

```
Пост 1/3

<текст поста 1 — начинается с хук-строки>

———

Пост 2/3

<текст поста 2>

———

Пост 3/3

<текст поста 3>
```

- **Маркер** первой строки каждого поста: `Пост N/TOTAL` (регэксп `^Пост\s+\d+/\d+\s*$`).
- **Разделитель** между постами: строка `———` (три em-dash) в окружении пустых строк.
- Zernio публикует **каждый пост отдельным постом** в Threads, БЕЗ маркера в контенте.

**Backward compat:** если в поле нет маркеров `Пост N/TOTAL` (старые записи, ручной ввод) — сплитим только по `———`. Если нет и разделителя — публикуем весь текст как один пост.

---

## Алгоритм

```
1. Получить raw_text:
   - row → fields["Тредс"] или fields["Тред"]
   - path → читать треды.md (или threads.md)

2. Сплит на посты:
   posts = split_thread_text(raw_text)

   Логика split_thread_text:
   a) Разделить raw_text по regex \n\s*———\s*\n → чанки
   b) Для каждого чанка:
      - Обрезать whitespace вокруг
      - Если начинается с "Пост N/TOTAL" (regex ^Пост\s+\d+/\d+\s*$) → убрать эту строку и следующую пустую
      - Если чанк пустой после чистки → пропустить
   c) Вернуть список текстов постов (обычно 1-3 штуки)

3. Валидация каждого поста:
   - Длина ≤ 500 chars (правило Threads)
   - Если больше — предупредить пользователя со ссылкой на пост, спросить обрезать или пропустить
   - Дедуп 24h: тот же текст недавно был? (warning, не блокер)

4. accountId = config.zernio.accounts.threads.account_id

5. Публикация в цикле (по одному post за раз):
   for i, post_text in enumerate(posts):
     posts_create({
       content: post_text,
       platforms: [{
         platform: "threads",
         accountId: "<config>"
       }],
       publish_now: true  // или scheduled_for: <ISO+i*60сек> если запрошено
     })

     Если ответ 409 / connection lost → НЕ retry (правило 1).
     Сразу posts_list(account_id=threads) → проверить публикацию.

     Запомнить post._id → в общий список published_ids.

     ⏱ Задержка 30 секунд между постами (чтобы Threads-очередь не путалась
        и посты не публиковались одномоментно = не выглядели «серией»).

6. Все published_ids → передать в workflow 05 (CONFIRM) для отслеживания.
```

---

## Проверки перед отправкой (для каждого поста в пачке)

- [ ] Text не пустой
- [ ] Длина ≤ 500
- [ ] Маркер `Пост N/TOTAL` уже срезан (не должен уйти в publish)
- [ ] accountId правильный (`config.yaml → zernio.accounts.threads.account_id`, не заглушка `{{...}}`)
- [ ] Если planned — `scheduled_for > now + 5 min`, для пачки — с шагом ≥30 сек

---
