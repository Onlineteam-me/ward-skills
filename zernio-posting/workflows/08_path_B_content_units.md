# Workflow — Путь B: публикация из «Единицы контента»

> **Когда:** триггер `/zernio-posting unit:<ID>` или «опубликуй принятые» или ссылка на запись в таблице «Единицы контента» (`{{TABLE_CONTENT_UNITS}}`).
> **Главное отличие от Пути A:** работаем с таблицей **«Единицы контента»**, НЕ создаём записей в «Публикации». Статус ставим в самой Единице.
>
> Подстановки: `{{TABLE_CONTENT_UNITS}}` = `config.yaml → teable.tables.content_units`; `{{FLD_UNIT_...}}` = `teable.content_unit_fields.*`. Имена полей в PATCH — из `teable.content_unit_field_names` (ниже — имена по умолчанию; у Ward они другие, см. README).

---

## Шаг 1 — найти строки для публикации

### Вариант 1A: явный триггер `unit:<ID>` (одна запись)
```
GET {{TEABLE_URL}}/api/table/{{TABLE_CONTENT_UNITS}}/record?filter={"conjunction":"and","filterSet":[{"fieldId":"{{FLD_UNIT_ID}}","operator":"is","value":<ID>}]}
```
Получить одну запись по полю «ID» (у Ward — «№», целое число).

### Вариант 1B: «все принятые» (пачка)
```
GET {{TEABLE_URL}}/api/table/{{TABLE_CONTENT_UNITS}}/record?filter={"conjunction":"and","filterSet":[{"fieldId":"{{FLD_UNIT_STATUS}}","operator":"is","value":"<content_unit_ready_status>"}]}
```
Все строки со Статус = `config.yaml → teable.content_unit_ready_status` (по умолчанию «Принято»; поле `{{FLD_UNIT_STATUS}}` — см. `config.yaml → content_unit_fields`).

🔴 **Брать только Статус = `content_unit_ready_status`.** Строки со статусом `content_unit_rework_status` («На правки» — редактор просит переделать) исключить.

🔴 **Внутри Принятых — проверить per-format статусы**, чтобы не дублировать:
- Если `Post Insta`=«Опубликован» → IG-формат пропустить.
- Если `Threads пост`=«Опубликован» → Threads-формат пропустить.
- Если оба «Опубликован» → строку целиком пропустить (всё уже отправлено).

## Шаг 2 — прочитать поля каждой строки

Из `config.yaml → content_unit_fields`:
- `koncept` — для имени папки на компьютере
- `formaty` — multipleSelect: какие платформы нужны (Карусель → IG, Тред → Threads, и т.д.)
- `podpis_k_karuseli` — текст для IG (caption)
- `tred` — текст для Threads
- `papka_unit` — локальный путь к папке, где лежат медиа
- `id_number` — ID для трассировки
- `post_insta` — текущий per-format статус IG
- `threads_post` — текущий per-format статус Threads

## Шаг 2.5 — инициализировать per-format статусы в «Не опубликован»

🔴 **ОБЯЗАТЕЛЬНЫЙ шаг** перед публикацией. Если `Post Insta` или `Threads пост` пустые (null/empty) — выставить «Не опубликован» прямо сейчас, не ждать конца пайплайна.

**Зачем:** таблица «Единицы контента» должна всегда явно отражать статус. Пустое поле — неопределённость, которая путает при просмотре таблицы.

```bash
# Определяем что нужно обнулить:
# - post_insta пустой И «Карусель» есть в Форматах → ставим «Не опубликован»
# - threads_post пустой И «Тред» есть в Форматах → ставим «Не опубликован»
# - Если оба пустые — пишем в один PATCH сразу оба поля

# Пример: оба пустые (наиболее частый кейс при первом взятии юнита)
PATCH {{TEABLE_URL}}/api/table/{{TABLE_CONTENT_UNITS}}/record/<recId>
{
  "fieldKeyType": "name",
  "record": {
    "fields": {
      "Post Insta": "Не опубликован",
      "Threads пост": "Не опубликован"
    }
  }
}

# Пример: только Threads пустой (IG уже «Опубликован»)
PATCH {{TEABLE_URL}}/api/table/{{TABLE_CONTENT_UNITS}}/record/<recId>
{
  "fieldKeyType": "name",
  "record": {
    "fields": {
      "Threads пост": "Не опубликован"
    }
  }
}
```

**Логика инициализации:**

| Текущее значение | Действие |
|---|---|
| `null` / пустое | PATCH → «Не опубликован» |
| `"Не опубликован"` | Уже установлено — не трогать (экономим запрос) |
| `"Опубликован"` | Не трогать — уже опубликовано (и будет пропущено в Шаге 1) |

🔴 Инициализацию делаем **до** скачивания медиа и отправки в Zernio. Если пайплайн упадёт посередине — статус в таблице уже будет «Не опубликован», а не пустым.

## Шаг 3 — найти медиа (только локально)

🔴 **Медиа ищем только на компьютере.** Обычно оно уже лежит локально после генерации `/carousel` или конвейера `parsing-ward`. Сначала — путь из поля «Папка с медиа», потом архив и `source_hints`.

### 3A — проверить локальные папки

Ищем в `config.yaml → local.archive_root` + `local.archive_by_type`:

```bash
# Базовый путь — из config.yaml → local.archive_root
ARCHIVE="<config.local.archive_root>"

# Варианты имени папки (проверяем по порядку):
# 1. <ID>_<slug>  (напр. 12_stop_loss_basics)
# 2. <slug>       (напр. stop_loss_basics, стоп_лосс_без_паники)
# 3. <koncept>    (полное название концепта из поля koncept)

# Для карусели:
ls "$ARCHIVE/Карусели/" | grep -i "<slug или ID>"

# Для тредов:
ls "$ARCHIVE/Тредс-посты/" | grep -i "<slug или ID>"

# Также проверяем source_hints из config.yaml
```

Также проверяем `source_hints` из `config.yaml` — там могут быть папки с ещё не архивированным контентом.

**Если нашли папку локально** — используем её напрямую. Проверяем содержимое: `01_*.jpg` … `NN_*.jpg` (+ `*.mp4` если есть).

**Если локально не нашли или папка пустая** — это не ошибка пайплайна: формат пропускаем с предупреждением «нет медиа для юнита <ID>», per-format статус остаётся «Не опубликован», и спрашиваем пользователя путь. Облачные диски не используются.

## Шаг 4 — публикация через Zernio MCP

По форматам из «Форматы»:

- **«Карусель»** → IG Carousel (10 слайдов JPG). Caption = `podpis_k_karuseli`. См. `workflows/03_post_ig_carousel.md` (тот же flow Zernio MCP).
- **«Тред»** → Threads-пост. Text = `tred`. См. `workflows/02_post_threads.md`.
- **«Видео (сам)» / «Видео (аватар)»** — пока **не публикуем** (нет готового видео-файла, есть только сценарий). Помечаем в Комментарии «видео ждёт записи».
- **«Статья»** — на платформы IG/Threads не публикуем. Это для блога отдельным процессом.
- Перед публикацией каждый текст — через `knowledge/ward_brand_check.md`.

🔴 Соблюдать **правила** Zernio MCP из основного `SKILL.md` (409 не retry, scheduled_for > now+5мин, media_items top-level, camelCase, IG max 10 слайдов, Threads-пачка по одному посту).

## Шаг 5 — обновить per-format статусы в «Единицы контента»

🔴 Статус **самой строки** НЕ трогаем (остаётся как был). Меняем только per-format статусы.

После каждой успешной публикации:
```
# Если опубликовали IG карусель или Reel:
PATCH {{TEABLE_URL}}/api/table/{{TABLE_CONTENT_UNITS}}/record/<recId>
{"fieldKeyType":"name","record":{"fields":{"Post Insta":"Опубликован"}}}

# Если опубликовали Threads-тред:
PATCH {{TEABLE_URL}}/api/table/{{TABLE_CONTENT_UNITS}}/record/<recId>
{"fieldKeyType":"name","record":{"fields":{"Threads пост":"Опубликован"}}}

# Если опубликовали оба:
PATCH {{TEABLE_URL}}/api/table/{{TABLE_CONTENT_UNITS}}/record/<recId>
{"fieldKeyType":"name","record":{"fields":{"Post Insta":"Опубликован","Threads пост":"Опубликован"}}}
```

Это даёт чистую картину «что из этой строки уже ушло»: зелёный per-формат = опубликовано.

🔴 **НЕ создаём запись в «Публикации».** Путь B живёт только в Единицах (правило: не дублировать). Детали публикации — в [zernio.com dashboard](https://zernio.com).

## Шаг 6 — уведомление

```
✓ Опубликовано из Единицы контента №12:
  • IG Carousel: <ссылка из Zernio>   → Post Insta=Опубликован
  • Threads: <ссылка из Zernio>       → Threads пост=Опубликован
```

Если несколько строк за раз (триггер «опубликуй принятые») — кратко перечислить ID + ссылки + что обновлено.
